## 二、更正：三条 P0 误报

初版清单把这三条列为 P0 遗漏，实际都已自动跟随：

  getFileStreamPath(name)         Context 默认实现是 makeFilename(getFilesDir(), name)
                                  getFilesDir 已合成 -> 自动跟随
  getPackageCodePath()            返回 ApplicationInfo.sourceDir
  getPackageResourcePath()        同上，走 sourceDir/publicSourceDir

实测依据 PackageManagerProxy.kt L752-758（已有 pathFidelity 分支）：
    dataDir = syntheticDataDir(pkg)
    nativeLibraryDir = syntheticLibDir(pkg)
    sourceDir = syntheticApkPath(pkg)
    publicSourceDir = 同上

教训：这是本轮第三次「凭印象判定遗漏 -> 实际已覆盖」。
判断某路径有没有合成，必须搜代码里有没有**设置它**的地方，
不能只看 VirtualContext 有没有 override（ApplicationInfo 的字段在 PackageManagerProxy 里设）。

## 三、本次真正补齐的四处

1) VirtualConstants 新增 syntheticMediaDir(pkg)
     /storage/emulated/0/Android/media/<pkg>

2) VirtualContext.getExternalMediaDirs() 加 pathFidelity 分支

3) PackageManagerProxy：deviceProtectedDataDir / credentialProtectedDataDir = dataDir
   （加密存储目录同样会暴露沙箱）

4) NativeHookBridge.setupAppRedirections 新增 4 条 media 规则：
     /storage/emulated/0/Android/media/<pkg>/  -> <sandbox>/sdcard/Android/media/<pkg>/
     /sdcard/Android/media/<pkg>/              -> 同上
     以及两者无尾斜杠变体

**第 4 条是「只误导、不危害读写」的落点**：只合成路径而不加规则，
guest 拿到假路径后读写会直接失败 —— 那不是误导，是弄坏。

## 四、Environment / MediaStore 的结论（不变）

  Environment.getExternalStorageDirectory()      -> /storage/emulated/0，不含包名，不需要改
  Environment.getExternalStoragePublicDirectory  -> 同上
  MediaStore.*                                   -> 走 content:// URI，不返回绝对路径
  StorageVolume.*                                -> 卷路径，不含包名
