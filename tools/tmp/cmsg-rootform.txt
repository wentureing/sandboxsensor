fix(path): 族根匹配语义（ROOT_FORM）—— T39/T41 转绿，Java 与 C++ 同步

## 为什么
`syntheticDataDir(pkg)` = `/data/user/0/<pkg>`（无尾斜杠，AOSP 形态），而规则注册的是带尾斜杠的
前缀 `/data/user/0/<pkg>/` → startsWith 不成立 → 族根不被翻译 → T39/T41 红。
根因与三个方案的比较见 docs/输出/记录/记录-T39-T41-族根路径无规则.md。

## 修法（方案 A：扩匹配语义，不加规则）
以 '/' 结尾的规则**同时拥有自己的根形态**（去掉尾斜杠的那个字符串）：
- 命中条件：path == from.dropLast(1)
- 有效长度：from.length - 1（参与最长匹配）
- 返回：to.trimEnd('/')
- 平局：真正的前缀优先（`/sdcard` 与 `/sdcard/` 同时存在时的确定性）

## 改动（Java 与 C++ 必须同提交，否则层间分叉）
- NativeHookBridge.translatePath：ROOT_FORM 判定 + tie-break + 根命中返回去斜杠目标
- native-hook.cpp redirect_path：同一语义（新增 trim_trailing_slashes）
