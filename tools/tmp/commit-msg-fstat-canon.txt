feat(hook): 补 Linux.fstat 与 UnixFileSystem.canonicalize0 —— 「路径长相零暴露」的前置条件

## 目标（用户定义）

  不是让物理路径真实（Gaia 式镜像会暴露容器包名 com.app.hider.master.pro.cn），
  而是「路径长相零暴露 + 读写有效」：

    guest 看到：/storage/emulated/0/Android/data/mark.via/files
    物理位置：  <sandbox>/sdcard/Android/data/mark.via/files
    靠 hook 保证每个 syscall 都翻译

  这比 Gaia 更好（零暴露），但对 hook 完整度的要求高得多 —— 漏一个就露馅。

## 本次补的两个缺口（改返回值之前必须先有）

### 1) Linux.fstat(FileDescriptor) -> StructStat

  FileInputStream / IoBridge 构造时会 fstat 拿长度与类型。
  另外「返回宿主形态路径」之后，调用方常先 stat 路径再 fstat 交叉验证。

  实现：java_io_get_fd() 反射 FileDescriptor.descriptor 取 int fd，
        ::fstat（GOT 表里没有 fstat，不会递归），失败抛 ErrnoException。
        日志：ufs-alias fstat: fd=N -> size=... mode=0...

### 2) UnixFileSystem.canonicalize0(String, boolean) -> String

  **这是「返回宿主形态路径」的硬前提**：
  若不 hook，getCanonicalPath() 会给出真实沙箱绝对路径
  （/data/user/0/com.nextvm.app/files/virtual/data/<inst>/...），
  比现在的暴露更彻底 —— 改返回值反而会变得更糟。

  AOSP 语义：失败时 JNU_ThrowIOExceptionWithLastError(env, "Bad pathname")，
  **不返回 null**。实现：::realpath（GOT 表里没有 realpath），
           失败抛 IOException，成功返回 String。
  日志：ufs-alias canonicalize0[xlat]: <src> -> <canonical>

## 依赖修正

  原实现引用了不存在的 real_fstat / real_realpath，且用了未 include 的 PATH_MAX。
  核实 GOT 表（native-hook.cpp L1681 附近）只有 "stat"，没有 fstat / realpath，
  所以直接用 ::fstat / ::realpath 是安全的（不会递归到自己的 hook）。
  另加 #include <limits.h> 以提供 PATH_MAX。

## 审计

  jni-sig-audit 对设备 dex 验证：18/18 OK，含新增的
    fstat          (Ljava/io/FileDescriptor;)Landroid/system/StructStat;
    canonicalize0  (Ljava/lang/String;Z)Ljava/lang/String;
