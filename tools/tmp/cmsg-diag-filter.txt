fix(hook): hook 日志跳过容器自身诊断文件 —— 否则 debug-trace.log 会把日志配额吃光

## 一、现场：诊断日志被自己淹没

装 b992ba4 后查 `JavaIo open`，结果整页都是：

    JavaIo open: /data/user/0/com.nextvm.app/files/debug-trace.log (flags=0x441)
    JavaIo open: /data/user/0/com.nextvm.app/files/debug-trace.log (flags=0x441)
    ...（20+ 次，一直到最后）

原因：`hooked_java_linux_open` 只打印前 200 条（`n <= 200`），而容器的
DebugTrace / Diagnostics / Breadcrumb 每次写日志都会 open 一次同名文件，
guest 进程里同样会被 hook 拦到 —— 于是前 200 条配额全被 `debug-trace.log` 占满，
真正想看的 guest 文件访问（比如 via 有没有读过 homepage2.html）根本看不到。

## 二、修法

新增 `is_container_diag_path(const std::string&)`，匹配这些标记：

    /debug-trace.log
    /checks.log
    /breadcrumb-
    /stackdump-
    /webviewwarm-
    /webviewwatch-

`hooked_java_linux_open` 里：

    g_java_io_open_total.fetch_add(1);
    if (!is_container_diag_path(real)) {     // 诊断文件不计入配额
        int n = ++g_java_io_open_logs;
        if (n <= 200) LOGI("JavaIo open%s: %s (flags=0x%x)", ...);
    }

注意 total 计数仍然累加（统计口径不变），只是不打日志。

## 三、为什么这是必要的

本轮排查「via 主页不可用 / 离线列表为空」时，两个关键判断都卡在这里：

  * 无法确认 via 到底有没有 open 过 homepage2.html
  * 无法确认 via 列举 offline 之后做了什么

`list0` 那边已经能看到 `-> 3 entries`（readdir64 修复生效），
但 `open` 侧被诊断文件淹没，导致「via 有没有读文件内容」这个关键问题无法回答。
