# T2-pre2：去 UI 化之后仍崩溃 —— 根因是 `super.onCreate()` 里的图标加载

- 日期：2026-11-22 15:17（设备时间）
- 设备：vivo V2463A / Android 15 / API 35
- 容器：`com.nextvm.app` v1.0.0-alpha01（原版）
- 探针：`com.sandbox.probe`（容器内实例 `com.sandbox.probe_1795331863573`）
- 日志：`probe-reports/dump-151715.txt`（212 KB，15:17:22 → 15:19:04，已清空缓冲后采集）

---

## 1. 用户操作

1. 导入 APK 后**连续启动两次**：没看到 Activity，**没有崩溃**
2. 退出容器 → 重新进入 → 启动一次：**容器立即崩溃**

日志对应：3 次 `:p0` 进程启动（pid 10383 / 10741 / 10960），其中 2 次产生完整 PHASE + FATAL，1 次（10741）没有 PHASE 记录。

## 3. 崩溃根因（完整栈）

```
FATAL EXCEPTION: main   Process: com.sandbox.probe, PID: 10383
java.lang.RuntimeException: Unable to start activity
  ComponentInfo{com.sandbox.probe/com.sandbox.probe.ProbeActivity}:
  android.content.res.Resources$NotFoundException: Resource ID #0x7f0a0000

Caused by: android.content.res.Resources$NotFoundException: Resource ID #0x7f0a0000
  at ResourcesImpl.getValueForDensity(ResourcesImpl.java:497)
  at Resources.getDrawableForDensity(Resources.java:1110)
  at Resources.getDrawable(Resources.java:1050)
  at android.content.Context.getDrawable(Context.java:994)
  at com.android.internal.widget.ToolbarWidgetWrapper.setIcon(ToolbarWidgetWrapper.java:322)
  at com.android.internal.widget.ActionBarOverlayLayout.setIcon(ActionBarOverlayLayout.java:826)
  at com.android.internal.policy.PhoneWindow.setDefaultIcon(PhoneWindow.java:2014)   ← ★
```

**关键结论：崩溃发生在 `super.onCreate(savedInstanceState)` 内部**，是框架创建 Window/ActionBar 时用
`ActivityInfo.icon` 去加载应用图标。容器把宿主 stub 的 `ActivityInfo.icon`（`0x7f0a0000` = 宿主应用图标）
原样留给了 guest ActivityInfo，而 guest 的 Resources 里没有这个 ID → `NotFoundException`。

> **上一轮"删掉 TextView 就能跑"的假设被推翻**：崩溃点在 `super.onCreate()`，与探针自己的 UI 代码无关。
> 任何继承 `Activity` 的 guest 组件都会踩到（除非 theme 不创建 ActionBar，或容器修好 icon 映射）。

## 5. 两个待查项

1. **`EARLY` 分块一条都没有** → `Report.flushEarly` 没有生效。
   - 可能性 A：本次导入的 APK 仍是旧版本（不含 `flushEarly`）
   - 可能性 B：`flushEarly` 内 `ctx.getFilesDir()` 在 Provider 阶段抛异常，被内部 catch 后 `Log.w` 也没落盘
   - 需核对：容器沙箱里的 APK 是否等于最新构建产物（比对 size / dex 内容）
2. **第三次启动（pid 10741）没有 PHASE** → 这次连 Provider 都没初始化，说明容器在更早阶段就失败了（可能是 Resources 初始化或 APK 校验）

---

## 6. 下一步（结论明确）

1. **探针放弃 Activity 入口**：把 `ProbeRunner` 的触发移到 `ContentProvider.onCreate` 的后台线程
   （Provider 阶段容器已证明可用），Activity 仅保留为可选入口
2. 若仍要保留 Activity：给 manifest 加 `android:icon="@android:drawable/sym_def_app_icon"` 之类的**系统资源**，
   避开容器未映射的 `0x7f0a0000`；但这只是绕过，容器缺陷仍在
3. 容器侧 P0 缺陷（供后续修改 ShitJumpingVM 时参考）：
   - 替换 `ActivityInfo` 时必须同步重映射 `icon` / `logo` / `theme` / `banner` 等资源 ID
   - `getResources()` 抛异常是更底层的问题（breadcrumb `getResources()=THREW`）
