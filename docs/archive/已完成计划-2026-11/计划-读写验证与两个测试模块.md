## 一、两个测试模块的定位（不能互相替代）

| 模块 | 跑在哪 | 能验证 | 不能验证 |
| --- | --- | --- | --- |
| **① 探针 APK**（`probe/`，`probe-build.yml`） | **真机 + 容器内** | native hook 是否真的拦截了 syscall、沙箱与宿主的**实际落点** | 逻辑分支（要跑全 app 才有覆盖）、release 构建差异 |
| **② 模块单元测试**（`*.kt`，`module-test.yml`） | **CI 纯 JVM / Robolectric** | 纯 Kotlin 逻辑：规则匹配、优先级、状态机、编解码 | 任何 native 行为、真实文件系统、进程隔离 |

**关键认知**：
> 容器这次改的是 **native GOT hook**，那部分**只有探针（真机）能验证**。
> 但"规则怎么匹配"是**纯 Kotlin**（`translatePath`），**模块测试能覆盖** ——
> 这是本次能用 CI 兜住的部分，价值很高（不依赖真机就能防回归）。

## 二、模块 ①：探针 —— 怎么更新、怎么用

### 2.1 已加的 F01–F08（本轮已提交 `79e1992`）

| ID | 内容 |
| --- | --- |
| F01/F02 | sandboxRoot / hostRoot 的实际路径 |
| F03 | `mkdir` vs `mkdirs` |
| F04 | write + read 回读 |
| **F05** | **`list()` 是否能看到刚写的文件**（验 `opendir`） |
| F06 | `renameTo` + 结果列表 |
| F07 | `delete` + `stillExists` |
| **F08** | **宿主形态路径**（`.../data/<getOpPackageName()>/files/fsprobe`） |

### 2.2 还需要补的（本轮之后，按优先级）

| # | 补什么 | 为什么 |
| --- | --- | --- |
| **A** | **自动判定 PASS/FAIL**，不只是打印 | 现在 F05/F06 的判据要人眼看 `names=`。应输出 `verdict=pass/fail` + `reason=` |
| **B** | **两侧对照**：同一操作在 `sandboxRoot` 与 `hostRoot` 各做一次，比对"宿主侧是否真的没多出东西" | 只测沙箱侧无法证明"没逃到宿主" |
| **C** | **深度目录**：`mkdirs` 三层（`a/b/c`） | 验"逐级 mkdir"链路（`mkdir` 只建最后一级，父目录要靠应用自己逐级建） |
| **D** | **写入二进制 + 大文件**（1 MB） | 验"部分写/缓冲"路径，避免只测小文本 |
| **E** | **`File.getCanonicalPath()`** | 验 `realpath`（P4，当前未 hook —— 这条会明确暴露它是缺口） |

### 2.3 怎么用（操作步骤）

```powershell
# 1) 构建探针（等容器 CI 通过后再 dispatch，一次一个）
node tools/release/gh-api.mjs --dispatch probe-build.yml main

# 2) 装容器 + 装探针
adb install -r dist/<container>.apk
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.INSTALL --es path /data/local/tmp/probe-vNNN.apk

# 3) 容器内启动探针（跑 F 组）
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LAUNCH --es pkg com.sandbox.probe

# 4) 取报告（探针会把 probe-report.json 写到 files/ 与 external）
adb exec-out run-as com.nextvm.app cat <instance>/files/probe-report.json

# 5) 关键看 F05 的 names、F08 的 path，并用设备侧核对宿主目录
adb shell "ls -la /storage/emulated/0/Android/data/com.nextvm.app/files/fsprobe/"
```

### 2.4 探针侧的"金标准"

| 现象 | 判定 |
| --- | --- |
| F05 `names` 含 `a.txt` | `opendir` 重定向生效 ✅ |
| F08 `path` 指向沙箱、且宿主 `fsprobe` 目录**不存在或为空** | 宿主兜底生效 ✅ |
| F03 `mkdirs=true` 但随后 F04 写入失败 | **目标目录树不完整**（本轮修的重点） |
| 宿主 `fsprobe` 里有真实文件 | 兜底失效 ❌ |

## 三、模块 ②：单元测试 —— 怎么更新、怎么用

### 3.1 现状（5 个测试类，全在 `common` / `sandbox`）

| 测试 | 覆盖 |

**缺口：`core:hook` 零测试** —— 而 `translatePath` / `addPathRedirection` 都是**纯 Kotlin**。

### 3.2 要新增的测试（这是本轮最能用 CI 兜住的部分）

**新建 `core/hook/src/test/.../NativeHookBridgePathTest.kt`**（纯 JVM）：

| # | 测试 | 断言 |
| --- | --- | --- |
| T1 | **最长前缀优先** | 同时注册 `/storage/emulated/0/` 与 `/storage/emulated/0/Android/data/com.nextvm.app/`，对后者的路径必须命中**后者**的映射 |
| T2 | **宿主兜底规则真的注册了** | `setupAppRedirections(guest, id, sandbox)` 后，`translatePath(".../data/com.nextvm.app/files/x")` 应返回 `<sandbox>/host_ext/files/x` |
| T3 | **guest 自身路径不受影响** | `.../data/mark.via/...` 仍映射到 `external_data/` |
| T4 | **未命中时原样返回** | `translatePath("/sdcard/other.txt")` 视规则而定；至少 `/data/app/x` 应原样 |
| T5 | **hiddenPaths 优先于重定向** | 注册重定向后再 `hiddenPath`，应返回 `/dev/null` |
| T6 | **重复注册同前缀时后者覆盖** | 行为记录（map 语义） |
| T7 | **`HOST_EXTERNAL_FALLBACK=false` 时规则不注册** | 开关可回退的证明 |

**关键**：这 7 条**不需要真机、不需要 native** —— 直接跑在 CI，2 分钟出结果。
它能把"规则层"的正确性锁死，让真机验证只需关注"native 有没有真的调用 `redirect_path`"。

### 3.3 需要的前置改动

| 项 | 内容 |
| --- | --- |
| `core/hook/build.gradle.kts` | 加 `testImplementation(libs.junit)` + `testOptions { unitTests.all { testLogging { showStandardStreams = true } } }` |
| 测试可见性 | `translatePath` 目前是 `public` ✅；`setupAppRedirections` 也是 `public` ✅ —— 无需改可见性 |

### 3.4 怎么用

## 六、本轮改动范围的收敛（按用户第 1 点）

**"暂不追求拒绝删除的安全设计"** → 本轮及下一轮聚焦：

| 保留 | 暂缓 |
| --- | --- |
| `open` / `openat` / `fopen`（原有） | `unlink`/`unlinkat`/`rmdir` 的**验收标准**（代码在，但不作为通过条件） |
| `mkdir` / `mkdirat`（本轮新增） | `realpath` 的修复（先让探针 E 暴露问题） |
| `opendir`（本轮补重定向） | `statfs` |
| `rename`（本轮新增） | Java 层 `JavaIoHooks` 扩展 |

**理由**：读写链是"能用"的前提；删除是"不损坏"的前提。用户明确先要"能用"。

## 七、一句话

> **单元测试锁"规则逻辑"（T1–T7，纯 JVM，2 分钟），探针锁"native 是否真的生效"（F01–F08，真机）。**
> 两者不重叠、不替代。本轮 CI 通过后，**先看 `fs.stats` 的 `translated` 是否 > 0** ——
> 那是最便宜的分诊点：`translated=0` 说明规则没命中（改 Kotlin 就行），
> `translated>0` 但 `fail>0` 说明目标目录树不完整（改 native 兜底）。

## 八、可行性核实（已实测，非推测）

| 项 | 结论 | 依据 |
| --- | --- | --- |
| `translatePath` 能纯 JVM 测 | ✅ | L708-729 只读 `hiddenPaths`（Set）和 `pathRedirections`（Map），**不碰 JNI** |
| `addPathRedirection` 在测试里安全 | ✅ | L369-377：先写 Kotlin map，`if (nativeHooksAvailable)` 才调 JNI；纯 JVM 下该标志恒为 `false` |
| `setupAppRedirections` 可调用 | ✅ | `public`，且内部同上 |
| `NativeHookBridge` 可实例化 | ✅ | `class NativeHookBridge @Inject constructor()` —— 无参构造，测试里直接 `NativeHookBridge()` |
| Timber 在测试里 | ⚠️ 无 tree 时是**无操作**，不抛异常 | Timber 默认行为 |
| 缺的只有 | `core:hook/build.gradle.kts` 的 `testImplementation(libs.junit)` + `testOptions` | 当前 `dependencies` 里没有 |

**所以 T1–T7 不需要任何真机、不需要 Robolectric、不需要 native 库。**
"`## 三、3.3 需要的前置改动`"里说的内容已确认无误。
