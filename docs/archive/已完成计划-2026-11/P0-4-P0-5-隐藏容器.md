# P0-4 / P0-5：隐藏容器（容器包不可见 + dataDir 不可访问）

> 原 §零点六


### 0.6.1 为什么这两件排在 native hook 之前

依据 `docs/架构/架构-检测面与优先级.md` 的交叉矩阵：

| 检测点 | 发现可能性 | 拦截难度 | 现状 |
| --- | --- | --- | --- |
| **`P13` 容器包可见** | ★★★★ | 🟢 容易 | ❌ |
| **`P16` 容器 dataDir 可 stat** | ★★★ | 🟢 容易 | ❌ |

**两者都是 OWASP MASWE-0052 点名的 "package structure" 检测面。**

### 0.6.2 P0-4：容器包不可见（0.5 天）

| 项 | 内容 |
| --- | --- |
| **目标** | guest 调 `getPackageInfo("com.nextvm.app")` / `getInstalledPackages()` 时看不到容器 |
| **改哪里** | `core/binder/.../PackageManagerProxy.kt`（850 行） |
| **改哪些入口** | `getPackageInfo` / `getApplicationInfo` / `getInstalledPackages` / `getInstalledApplications` / `resolveActivity` / `queryIntentActivities` / `getPackagesForUid` |
| **代码量** | ~60 行（5–7 个入口 + 一个 `isContainerPackage()` 判断） |
| **难点** | ①要找出**所有**暴露包名的入口 ②**不能影响容器自己**（容器内部可能查自己）→ 用 `callerResolver.isGuestProcess()` 区分 |
| **验证** | 探针 `P13` 从 `visible` 变 `hidden`；容器自身功能不坏（能装 guest、能启动） |
| **风险** | 中 |
| **回退** | `git revert` |

### 0.6.3 P0-5：容器 dataDir 不可访问（1 天，与 P0-4 同批做）

| 项 | 内容 |
| --- | --- |
| **目标** | guest 对 `/data/user/0/com.nextvm.app`、`/data/data/com.nextvm.app` 的 `stat`/`access`/`open` 返回 `ENOENT`，且 `opendir("/data/data")` 列表里没有它 |
| **改哪里** | `native-hook.cpp` 的 `g_hidden_paths` + `hooked_opendir` |
| **必须改三处** | ①`is_path_hidden` 改成**前缀匹配**（现在是精确匹配，连子路径都不隐藏）②加容器两个前缀 ③**`readdir` 过滤** |
| **代码量** | ~80 行（前缀匹配 10 行 + `DIR*` 包装 60 行 + 调用 10 行） |
| **难点** | ①**不能藏掉容器自己需要的**（容器主进程要读自己的 dataDir）→ 按进程判断 ②`readdir` 过滤要维护 `fd → 过滤器` 的映射 |
| **验证** | 探针 `P16` 从 `exists=true` 变 `exists=false`；再 `opendir("/data/data")` 确认列表里没有容器 |
| **风险** | **高**（容易把容器自己搞坏） |
| **回退** | `git revert`；或加开关 `NS_HIDE_HOST=0` |

**为什么必须一起做**：
> **只做 `stat` 不做 `readdir`，等于主动暴露矛盾** —— guest 用目录遍历就能发现容器。

### 0.6.4 探针 P29：验证 `mprotect` 可行性（0.5 天，前置调查）

| 项 | 内容 |
| --- | --- |
| **目标** | 在 guest 进程里对 `libc.so` 的 `.text` 做 `mprotect(PROT_READ\|PROT_WRITE)`，看返回值 |
| **为什么** | 这是 R2（inline hook libc）的**唯一前置未知** |
| **改哪里** | `probe/src/main/cpp/native_probe.cpp` 加一项 |
| **代码量** | ~25 行（`dladdr(dlsym("open"))` 拿 libc 基址 → 找 `.text` 段 → `mprotect` → 恢复） |
| **判据** | 成功 → R2 可行；`EPERM` → R2 只能靠 memfd 方案 |
| **风险** | 低（只改一页，立刻恢复） |
