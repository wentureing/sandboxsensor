## 二、拆分（尤其是 B4 系列）后的最小回归

按"能力不能丢"排序，**每次拆分后至少跑这 5 项**：

```powershell
# 1) 能力 8：诊断通道（一次探针就覆盖 D01-D05）
adb shell setprop debug.probe.suite diag
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LAUNCH_ACTIVITY \
  --es pkg com.sandbox.probe --es activity com.sandbox.probe.ProbeActivity
# 拉 <inst>/files/probe-report.json：D01-D05 全 ok

# 2) 能力 9：watchdog 转储（等 watchdog 触发，通常 guest 启动后数十秒）
adb shell run-as com.nextvm.app \
  head -3 files/virtual/data/<inst>/files/stackdump-<pid>.log
# 期望：==== <label> ==== / main looper queue: / when=+.. 

# 3) 能力 3：写入仍导沙箱
adb shell find /storage/emulated/0/Android/data/com.nextvm.app/files/ -type f
# 期望：空（只有空目录壳）

# 4) 能力 11：豁免仍生效
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.SPOOF_EXEMPT_LIST
# 期望：mark.via + loaded=true

# 5) 能力 2：guest 启动链
adb shell run-as com.nextvm.app tail -5 files/virtual/data/<inst>/files/breadcrumb-<pid>.log
# 期望：bind complete → ... → cb onActivityResumed
```

## 三、判据说明

| 结论 | 依据 |
| --- | --- |
| **B4-1 没有丢能力** | ① 函数体逐字搬运（脚本按行号抽取）；② 两个调用点仍在 `VirtualApplicationManager`（`scheduleGuestStackDumps` 内 `:970`、AW plugin probe 内 `:2584`），触发条件未改；③ 单测 `le32` G1–G5；④ 真机 `stackdump-5993.log` 80 KB、格式与拆分前一致 |
| `memdex` 探针里没出现 | 该能力**只对 AW/SecNeo 壳 guest** 触发（plugin probe 里判定 `application.javaClass.name`）；普通 guest（探针）跳过是设计行为，不是丢失 |
| 其余能力 | 见上表"最近验证"列 |
