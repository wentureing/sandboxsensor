### 4.2 `SettingsViewModel` 的三个开关：**纯 UI 装饰**

```kotlin
private fun toggleFileIsolation() {
    _uiState.update { it.copy(fileIsolationEnabled = !it.fileIsolationEnabled) }
    // 只改 UI 状态 + 弹 toast，不调用任何引擎方法
}
```

| 开关 | 默认值 | 实际效果 | 与 AntiDetectionEngine 的关系 |
| --- | --- | --- | --- |
| **File Isolation** | `true` | **无**（文件隔离一直生效，由 native hook 做） | **无** |
| **Permission Firewall** | `false` | **无**（P0-4 还没做） | **无** |
| **Verbose Logging** | `false` | **无**（debug 包的 LOGD 一直可见） | **无** |

**结论**：

> **Settings 里没有任何与 `AntiDetectionEngine` 相关的开关。**
> 三个开关都是纯 UI 装饰，**不是 AntiDetectionEngine 的开关**。
> 所以「开关没打开」不是 `AntiDetectionEngine` 未启用的原因 —— **它压根没有开关**。

### 4.3 `WebViewWatch` / `WebViewWarmup`：挂在恒假分支

- `WebViewWatch.kt` 170 行 + `WebViewWarmup.kt` 404 行
- 它们的 `schedule()` 调用在 `VirtualApplicationManager` 的 `if (fwApp != null)` 分支里
- `fwApp` 恒非空（实测 `framework makeApplication exit app=mark.via.BrowserApp`）
- **但仍无日志** → 需要单独查（可能 `runWatch` 内部不打日志）

## 五、建议的接线顺序

| 顺 | 项 | 工作量 | 收益 |
| --- | --- | --- | --- |
