## 三、可测试性分层（为什么有些行只能"真机"）

| 层 | 含义 | 启动链里的实例 | 现状 |
| --- | --- | --- | --- |
| **L1 决策** | 要不要做、走哪条分支 | `classNameOf`、`isShizukuProvider`、`isShizukuSecurityException`、`isPathFidelityGuest` | ✅ 全部纯 JVM 可测（27 条） |
| **L2 状态** | 内部状态机 | `StubRegistry`、`VirtualProcessManager`、`ApplicationRecord.state` | ✅ 纯 JVM 可测（24 条，record 状态靠契约 C4/C7 间接锁） |
| **L3 Java 执行** | 反射替换、实例化、`attachInfo`、`Instrumentation` 调用 | `create`、`build`、`invoke`、`initContentProviders.install`、`bindViaFrameworkLoadedApk` | ⚠️ **不可纯 JVM**（android.jar 是 `Stub!` 桩，构造即抛） |
| **L4 native** | GOT patch / syscall | `initNativeHooks`、路径重定向真实生效 | ❌ 只能真机 |

**结论**：启动链的**顺序与分支决策**已经可机读（L1+L2 = 契约 + 单测）；
**执行本身**（L3/L4）只能靠真机——这不是缺测试，而是 android.jar 的物理边界。

## 四、明确不可纯 JVM 测的清单（含原因）

| 对象 | 原因 | 替代证据 |
| --- | --- | --- |
| `GuestApplicationFactory.create` | 需要真实 `Application` / `AppComponentFactory` | 契约 **C4**（`instr newApplication` 顺序与计数）+ 日志 |
| `ApplicationInfoFactory.build` | `ApplicationInfo()` / `Bundle` / `PackageManager` 都是 stub | 探针 **J19/J20** + `VirtualConstants` 纯数据单测 |
| `ApplicationOnCreateInvoker.invoke` | 需要真实 `Instrumentation` 与 guest `Application` | 契约 **C5/C6**（onCreate 在 provider 之后、规则注册之前） |
| `ContentProviderInitializer.install` 的四类异常分支 | 需要能"装失败"的真实 provider 与 ClassLoader | 契约 **C5** 只覆盖了 `FAILED (bind continues)` 一条；其余三条无样本（见 §五 缺口 2） |
| `bindApplication` / `bindViaFrameworkLoadedApk` 编排 | 反射 `ActivityThread` / `LoadedApk` / `ContextImpl` | 契约 **C1/C2/C7/C8** + 真机 breadcrumb |
| native 装载 | 需真实 libc / GOT | 探针 N 系列 + `SELF_CHECK` S5/S8 |

## 五、剩余缺口（按风险排序）

| # | 缺口 | 影响 | 补法 |
| --- | --- | --- | --- |
| 1 | **framework 路径与 legacy 路径只有一条被覆盖** | 现有 4 份 golden 全走 `framework makeApplication`；legacy 路径（`bind complete (legacy path)`）零样本 | 采一份"frameworkLoadedApk=null"的样本（需要构造该条件，或找一个走 legacy 的 guest） |
| 2 | **provider 的 4 条异常分支只有 1 条有样本** | `NOT FOUND` / `SecurityException SWALLOWED` / `IllegalStateException SWALLOWED` 无 golden 证据 | 造 3 个探针 guest（缺类 / 缺权限 / 抛 ISE）分别采一次 |
| 3 | 时序（每阶段耗时）不锁 | 启动变慢不会被测试发现 | 采集脚本已记录总耗时（1s）；若要锁时序需另建"耗时预算"测试（非本阶段） |
| 4 | 真机回归未做 | B4-4a/4b 只做了静态 + 单测 | B4-4c 之后一次性：`SELF_CHECK`（ok=8）→ 探针 `round`（逐项一致）→ via 启动看 `bind complete` |
| 5 | `StubRegistry.release*` 生产未调用 | 每个 slot 启动 5 次后起不来（`STATUS.md` §2 #7） | 单测已能固定"release 后能再取"，但缺一条"stopApp 后 slot 可复用"的集成断言 |
