## 一、问题起点

探针 `P28` 测的是：**guest 进程能否写真实的 `/sdcard/Download/probe-wtest.txt`**。

```cpp
/ native_probe.cpp 的 P28
fopen("/sdcard/Download/probe-wtest.txt", "r")     / 读
fopen("/sdcard/Download/probe-wtest.txt", "r+")    / 读写
fwrite("HACKED", 1, 6, fp)                          / 写
```

**判据在容器外部**（`adb shell cat`）读真实文件：
- 仍是 `ORIGINAL` → 写被拦
- 变成 `HACKED` → **真实文件被改**

## 四、两个叠加的原因（分清主次）

| # | 原因 | 是否充分 | 证据 |
| --- | --- | --- | --- |
| **1** | **权限传导**：容器有 `MANAGE_EXTERNAL_STORAGE` → guest 作为子进程（同 uid）继承 | ✅ **充分** | Gaia/直接安装都没有 → `errno=13`；我们有 → 能写 |
| **2** | **native hook 未覆盖运行期加载的库**：`System.loadLibrary("probe")` 加载的 `libprobe.so` 的 GOT 没被 patch → 它的 `fopen` 是原始 libc | ⚠️ **不是必须**（因为权限就够了） | `import exempt` 日志 0 次；沙箱里无该文件 |

**正确的因果关系**：
```
容器申请 MANAGE_EXTERNAL_STORAGE
  → guest 继承（同 uid）
    → guest 的 fopen 走真实路径
      → DAC 放行
        → 写成功
```

**hook 未覆盖只是让"路径重定向"也没生效**，即使 hook 生效，guest 仍能写（因为重定向到沙箱的副本……但沙箱里没这个文件，所以会失败）。

**换句话说**：
- **如果有 hook** → `fopen("r+")` 被重定向到 `<沙箱>/sdcard/Download/probe-wtest.txt` → 沙箱无此文件 → `errno=2`
- **如果没有 hook** → 走真实路径 → 权限够 → 写成功

**所以两者是"或"的关系，都能导致不同结果**；但**实测表明 hook 没生效**。

## 五、最终结论

### 5.1 对用户三个问题的回答

| 问题 | 答案 |
| --- | --- |
| **是权限配置障碍还是上游缺陷？** | **都不是**。是我们自己申请了 `MANAGE_EXTERNAL_STORAGE`，且**它会传导给所有 guest** |
| **修复（p28/p29）是否危害 WebView？** | **谈不上危害** —— 它们改的 `hooked_fopen` 在运行期加载的库里**不会被调用** |
| **缺陷是否确实存在？** | **存在，但分两层**：①**权限传导**（充分条件，已确认）②**运行期加载库拿不到 GOT patch**（独立问题，见下） |

### 5.2 两条独立的行动项

| # | 行动 | 理由 |
| --- | --- | --- |
| **A** | **容器不申请 `MANAGE_EXTERNAL_STORAGE`**，导入改用 SAF | 消灭权限传导 → guest 的 `P28` 会变成 `errno=13`（与 Gaia 一致） |
| **B** | 修 L6（patch `libnativeloader`，见 `调研/记录-方向A可行性-native-loader-hook断点.md`） | 让路径重定向对运行期加载的库也生效（与 A 无关，独立问题） |

### 5.3 `is_import_read_exempt` 的最终定位

- 它**不是"修 guest 读不到文件"**，而是**"修容器主进程自己读不到文件"**
- 因为主进程装了 hook → `installApp` 的 `open` 被重定向 → 找不到 `/sdcard/Download/x.apk`
- **P0-3（主进程不装 hook）后，整个豁免机制可以删掉**

## 六、三条教训

1. **判据要选"真实路径存在、沙箱路径不存在"的样本**
   —— `N03`/`N06` 两条都失败（`errno=2`）**无法区分**"重定向后不存在"和"根本没重定向"
2. **"改了一个分支" ≠ "这个分支会被执行"**
   —— 靠 `import exempt` **日志 0 次**才发现 `hooked_fopen` 根本没被调用
3. **三方对照比单点观测可靠**
   —— "我们能写"这件事，只有对照 Gaia（`errno=13`）才定位到真因是权限
