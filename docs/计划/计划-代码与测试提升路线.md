# 计划：代码与测试的同步提升（2026-11-28）

- 起点（客观现状）：
  - 容器 `9c0d3e9`（G3 白名单 + 警告清零），**G3 有 1 个已知缺陷**（`prop_contains` 参数方向反了 ⇒ 白名单从未命中）；
  - 探针 `e1eaa75`（W-ext 六组 + `W-big` + `who` 修复，102 项）；
  - 已定论：**多进程模型**（主进程不装 hook，guest 进程 `:pN` / argv0=guest 包名）、`file://` MIME 规律、**读取在 guest 进程经 libc `open`**（`who=libjavacore.so` 22/24）、诊断模式 `applied=50` 证明系统库可 patch 但全量不可用。
  - 目标（用户）：① via 的 WebView/文件操作 ② MT 基础功能 ③ 跨应用 A→B ④ 采样驱动的深入欺骗。

## 一、总原则（每个阶段都必须"代码 + 测试"成对交付）

| 规则 | 内容 |
| --- | --- |
| **R1** | 每阶段 = 代码改动 + 同批测试（host 单测 / 探针项 / 真机判据三选一以上），不允许"先改后补"（规则 9） |
| **R2** | 判据必须能**证伪**：删掉被测分支，测试应变红（规则 18.1） |
| **R3** | 行为变更走 `docs/输出/变更/`；纯逻辑搬运走 host 向量 |
| **R4** | 每次容器编译只验证一个假设，产物名记录到变更文档 |

## 三、阶段 1：把"guest 假路径 + WebView 真读"做成可用能力（目标 1）

### 代码
| 项 | 内容 |
| --- | --- |
| **内容目录选型落地** | 依据 `册-WebView与file-MIME`：内容目录用 `/storage/emulated/0/vsandbox/<guest>/`（含 guest 包名安全，不含宿主包名） |
| **开关** | `debug.nextvm.webContentRoot = vsandbox\|sandbox`（默认 `sandbox`＝现状，行为不变） |
| **翻译规则** | 复用 `PathKinds`：给 `FILES` 族增加"可选的宿主形态"变体（不新增族） |
| **回退** | 关开关即回现状；不依赖 `MANAGE_EXTERNAL_STORAGE` 也能跑（探测失败自动回 `sandbox`） |

### 测试
| 层 | 内容 |
| --- | --- |
| Kotlin（纯 JVM） | `PathKindsTest`：`rulesFor(APP, "mark.via", sandbox, null)` 在 `webContentRoot=vsandbox` 时产出 `/data/user/0/mark.via/files/` → `/storage/emulated/0/vsandbox/mark.via/files/`；`=sandbox` 时产出原规则（**两分支都覆盖**） |
| 探针 | 新增 `W-ext-realpath`：用**迁移后的内容目录**再跑一次 `.html`，断言 `text/html` + `WVPAGE_OK` |
| 真机 | via 打开离线页：`document.contentType`、页面可交互（不再显示源码） |

### 判据
via 离线页正常渲染；`W2` 仍 `plain`（宿主包名问题独立，见阶段 2）；其他 guest 不受影响。

## 八、测试体系本身要补的三件事（跨阶段）

| # | 缺口 | 补法 |
| --- | --- | --- |
| T-1 | **探针项只记录不断言**：`W-ext-*` 的结果进 `wvprobe-result.txt`，`check-probe-ids` 看不到 | 把 W 结果并入 `probe-report.json`（`group="webext"`），让 CI 能对比 |
| T-2 | **报告重复 id**（`N11–N16`/`H1`/`P28` 各 2 次） | 合并时按 id 去重，保留晚的那条 |
| T-3 | **探针不证"生效"**：`applied` 只记数字，无断言 | 新增 `H2.lib_allow_applied`：断言 `applied` 增量符合 `libAllow` 预期（1 个库 ⇒ +1） |

这三项做完，G3 这类"以为开了其实没开"的问题就能被 CI 抓住。

## 十、明确不做（防止范围膨胀）

1. 不做 inline hook（除非阶段 0+1 都失败，且届时单独立项）；
2. 不打开 `NS_HOOK_SYSTEM_LIBS=1`（全量放大，历史两次崩溃）；
3. 不做多实例（M1–M8），直到单实例的 ①–④ 都稳；
4. 不为单个 app 硬编码（`if (pkg == "bin.mt.plus")` 一律禁止）；
5. 阶段 5 的欺骗不得影响 I/O 落点（只改"报告内容"）。
