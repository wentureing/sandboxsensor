## 三、批 2 的具体设计（采集重构，D3+D4）

### 3.1 三态可判定（解决 D3）

```
ContentProvider.onCreate()            ← 每进程 bind 必执行
  └─ 写 probe-alive.json {schema, pid, process, uid, ts, phase:"provider"}
       │
Activity.onCreate() 第 1 行
  └─ append 一行 "PHASE activity-started <pid> <activity>"
       │
每个实验：begin → 结果 → flush   （不再等全部跑完）
       │
结束：append "PHASE done"
```

判读：

| 观测 | 结论 |
| --- | --- |
| 无 `probe-alive.json` | 进程**没起来**（bind 失败） |
| 有 alive、无 `PHASE activity-started` | Activity 没进 onCreate（slot 被回收 / 崩溃在更早） |
| 有 started、无对应实验 begin/结果 | 卡在某个实验（最后一行即卡点） |
| 有 begin 无结果 | 该实验内部挂住（配合 `STUCK` 日志） |

### 3.2 单一输出点 + 增量 flush

- 只用 `getFilesDir()`（容器里 `run-as` 必可读）；
- 写入失败**显式记一行** `OUT FAIL <path> <异常>`（不再静默）；
- 每条结果 append 后立即 `flush()`。

### 3.3 并入统一报告（解决 D4）

- `WebViewProbeActivity` 的每条 W 结果写进同 schema 的 `entries[]`（`group="webext"`）；
- 由 `ProbeRunner` 在收尾时读取并合并（避免两套取数）；
- `check-probe-ids` 的 golden 增加 `webext` 组（`W-ext-private` / `W-ext-public` / `W2` / `W14` 等关键项）。

### 3.4 附带：自建共享目录判定（D1 的收尾）

`WebViewProbeActivity` 增加第三组：

```
W-ext-shared : 写 /storage/emulated/0/<自建目录>/wvprobe_ext_shared.html → 读 contentType
```

判读：`text/html` ⇒ **目标 1 的 WebView 路线定稿为"内容目录迁到共享存储自建目录"**；`text/plain` ⇒ 再换方向。
