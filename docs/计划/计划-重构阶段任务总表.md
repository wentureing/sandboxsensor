## 四、顺序与并行

| 原则 | 说明 |
| --- | --- |
| **一次一个 CI** | 不论 R1 还是 R2，同一时刻只有一个 `module-test`/`container-build` |
| **Kotlin 与 native 交替** | 两条线改的是不同文件树（`core/virtualization` vs `core/hook/cpp`），可交替提交；**不要同一提交混两条线** |
| **缺陷修复排在落点就位后** | R3-3/R3-4 依赖 R1-2（取证/编排已搬出，改一个文件即可） |
| **收尾必须全绿** | R4 前所有批 CI 绿、真机 5 项过 |

**推荐立即顺序**：`R2-0`（工具，零风险）→ `R2-1`（N1，建立样板）→ `R1-1`（f′）→ `R2-2`（N2）→ `R1-2`（g）→ …

## 五、风险与回退

| 风险 | 对策 |
| --- | --- |
| native 改动导致设备闪退 | 每批只搬纯逻辑；E 类 hook 入口不改；单独 commit 可 `git revert` |
| 适配器永久留存 | 台账 + `TODO(adapter:)` 计数纳入 R4 门禁 |
| 行为变更夹进重构 | 规则 10：R3 单独走变更文档，不进 R1/R2 |
| golden 按重构后实现推导 | 每批 T1 等价检查 + 契约测试兜底 |
| 批次过多导致 CI 排队 | 每批完成后立即触发下一次；不并行触发 |

## 六、明确不做（本阶段）

| 项 | 原因 |
| --- | --- |
| 多实例 M1–M8（VPMS/代理按 instanceId 改键、合成路径带 instanceId） | 用户 2026-11-27：顺序已同意但**暂不执行** |
| native E 类 hook 入口重写（`hooked_open` 等） | 风险最高、收益低；只搬它们调用的纯逻辑 |
| 换 hook 库（xHook/ShadowHook/Dobby） | 机制保留；只在 N4 借鉴过滤策略 |
| WebView `file://` MIME | 独立立项 |
| JNI 签名/`.so` 名/`NS_*` 语义变更 | 契约冻结 |
