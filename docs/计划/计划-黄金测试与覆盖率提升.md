> 而这两块恰好是最容易重构、也最容易静默出错的地方。

## 二、golden 的定义（本项目口径）

> **golden ≠ 覆盖率数字。golden = 锁定"当前正确行为"的输入→输出向量表。**
>
> 但要先分清两种用途（2026-11-25 用户补充）：
>
> | 用途 | 适用对象 | 目的 | 是否随后重构 |
> | --- | --- | --- | --- |
> | **A. 重构证据** | 会被改动的代码（`core:hook` 路径、`core:model` 槽位、`core:virtualization` 生命周期、`core:binder` 代理） | 重构前后"逻辑未变"可被机器证明 | ✅ 是 |
> | **B. 行为铆钉** | **很少修改、已稳定的代码**（`core:framework` 的解析/校验、`core:common` 诊断） | 防止**静默回退**；成本低、一次写好长期有效 | ❌ **不重构** |
>
> **判据**：一段代码要不要为"重构"补测试，先问「未来会不会改 + 职责是否混杂」。
> 两个都不是 → 只铆钉行为，不安排重构（避免为了重构而重构）。

| 层 | 内容 | 形式 | 用来判断什么 |
| --- | --- | --- | --- |
| **L1 纯函数向量** | 解析/校验/匹配/策略的 `(输入 → 期望输出)` | 测试代码内的数据表（不引外部资源，避免资源加载差异） | 重构时"逐字未变" |
| **L2 规则集快照** | `getPathRedirectSnapshot()` 的键值对 | 测试内联期望集合（K4 已是这个形式） | 数据表化改造前后 diff 为空 |
| **L3 结构自检** | "每族都有宿主形态"、"每族都有归属" | 断言（K6/W7） | 结构上不可能漏，替代事后检查 |

**golden 变更规则**：向量要改，必须在 `docs/输出/变更/` 里写"为什么行为要变"，否则视为回退。

### 3.2 需要"半个 Android"、只能部分测

| 文件 | 能测的部分 | 不能测的部分 |
| --- | --- | --- |
| `NativeLibValidator.getPrimaryAbi/getFallbackAbi` | — | 依赖 `android.os.Build.SUPPORTED_ABIS`（stub 为 null） |
| `SandboxManager` | 路径拼接（配合 `TemporaryFolder`） | `ensureDir` 的计数/缓存语义需真实 FS 行为 |
| `VirtualContext` | 只有 `shouldUseSyntheticContent` 这类抽出来的纯判据 | 构造需要 `Context` |

### 3.3 明确**不**做纯单测（靠探针/真机）

| 对象 | 原因 |
| --- | --- |
| `core:binder` 各 `*Proxy` | 需要 `ServiceManager`/`Parcel`/Binder 线程 |
| `VirtualApplicationManager` 启动链 | 反射 + `LoadedApk` + framework 内部结构 |
| WebView 相关（`WebViewWarmup`/`WebViewWatch`） | 渲染在 isolated 进程，容器不可介入 |
| `native-hook.cpp` | 需真机（GOT patch/JNI 注册）；可选方案：把纯函数抽到可在 host 编译的单元 |
| `SystemServiceProxyManager` | 全是 Android 服务接口 |

## 五、与拆包门禁的关系

> 拆包计划 §零 已定"先测试后拆"。本计划补上**具体顺序**：

```
G0（上一个 CI 绿）
  → T 批：给目标模块补齐 golden（本计划）
  → 该模块 golden 绿（专属 CI）
  → 才进入 G1/G2 拆包（每次两个职责）
```

**理由**：拆包时最容易发生的错误是"语义等价但没人能证明"。golden 向量就是
`check-refactor-equivalence.mjs`（静态）之外的**行为级**证据，两者互补。

## 六、验收判据

| 项 | 判据 |
| --- | --- |
| 编译 | 被测模块 `testDebugUnitTest` 绿 |
| golden 有效 | 每个向量都写明"为什么这个期望值对"（注释一句），不是复制当前输出 |
| 无 Android 依赖 | 测试不 import `android.*`/`androidx.*`（除第 3.2 节列出的例外） |
| 不破坏日志 | 不给被测代码加日志；测试不依赖 `DebugTrace` 输出 |
| 文档 | 本文件 + 各模块 `build.gradle.kts` 的测试依赖变更写进 `docs/输出/变更/` |
