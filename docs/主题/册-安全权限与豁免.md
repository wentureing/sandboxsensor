## 一、存储权限的真实状态（A 级，实测）

| 声明 | 设备实际 | 说明 |
| --- | --- | --- |
| `MANAGE_EXTERNAL_STORAGE` | **appops `allow`** | 唯一生效的存储权限（"所有文件访问"）；**干净安装会重置为 `ignore`**，脚本重授 |
| `READ_EXTERNAL_STORAGE` | `granted=false`，appops `ignore` | API 33+ 被 `READ_MEDIA_*` 取代；targetSdk 35 下**声明也不授予** |
| `WRITE_EXTERNAL_STORAGE` | `granted=false`，appops `ignore` | API 29+ 废弃；targetSdk ≥ 29 时不授予 |
| `android:requestLegacyExternalStorage="true"` | 仅 legacy flag | 只对 targetSdk ≤ 29 生效 ⇒ **本项无效果** |

**对路径方案的含义**：

| 路径 | 需要 | 结论 |
| --- | --- | --- |
| `/data/user/0/<pkg>/…`（内部） | 自有包 | ✅ |
| `/storage/emulated/0/Android/data/<pkg>/…` | 自有包，**零权限** | ✅ 但对 WebView `file://` 无效（含包名 ⇒ 嗅探） |
| `/storage/emulated/0/<不含包名目录>/…` | `MANAGE_EXTERNAL_STORAGE` | ✅ **WebView 内容目录首选** |
| 其他 app 的 `Android/data/<other>` | **不可访问**（Android 11+ 硬限制） | ❌ |

> **检测面提示**：guest 可通过 `PackageManager` 看到宿主的权限列表（`MANAGE_EXTERNAL_STORAGE` + `QUERY_ALL_PACKAGES` + 5 个 `FOREGROUND_SERVICE_*`），
> 这个组合本身很"多开器"。若做 L3 欺骗，这属于要遮的内容（PMS 代理已在，可裁剪）。

## 二、导入通道（实测结论）

| 通道 | 前提 | 备注 |
| --- | --- | --- |
| `/sdcard/Download/` | **`MANAGE_EXTERNAL_STORAGE = allow`** | `default` 时报 `APK file not found`；`allow` 后同包直接 `Success` |
| `/data/local/tmp/` | 644 即可，**无需额外授权** | 开发/自动化首选 |
| app 私有目录 | 容器自身可读 | 容器把 `/sdcard` 重定向到沙箱 |

**两条禁令**：
1. **不要用 `run-as` 验证应用权限**（`runas_app` 域 ≠ `untrusted_app` 域，结论不可迁移）；
2. **不要只凭 `ls -l` 推断可读**（还要过 SELinux + FUSE + appops）。

## 三、豁免名单（`SPOOF_EXEMPT_*`）与权限传导

| 机制 | 内容 | 结论 |
| --- | --- | --- |
| **豁免名单** | `mark.via` 等：**零路径欺骗但仍隔离**（`v143-datadir skip (whitelist)`） | 设计理念第三条的落地：只误导不危害读写；golden C9 固定 |
| **豁免增删** | `SPOOF_EXEMPT_ADD/REMOVE/LIST` 广播 | 运行时改，不改代码 |
| **权限传导（P28）** | guest 申请的权限 → 容器代为持有/映射 | `记录-P28与权限传导-完整结论.md`；`P28.sdcard_write` 在探针里可观测 |

**已知边界**：
- 豁免 = 不合成路径，**不等于**不隔离（I/O 仍落沙箱）；
- 改 `getOpPackageName()` 会破坏 appops 归因（`checkPackage` 抛 `SecurityException`）—— **禁止**。
