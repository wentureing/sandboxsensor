## 一、三套东西各管什么

| 体系 | 位置 | 测什么 | 取数 |
| --- | --- | --- | --- |
| **探针** `probe/`（`com.sandbox.probe`） | 独立 APK，导入容器跑 | **guest 视角**（路径/身份/native/UI/proc） | `probe-report.json`（+ WebView 的 `wvprobe-result.txt`） |
| **容器自检** `ContainerSelfCheck`（SELF_CHECK） | 容器内 | **容器动作是否可行**（S1–S8） | `files/checks.log` 的 `hookcheck ok=N fail=N` |
| **golden 契约** | 测试资源 | **启动链顺序**（C1–C12） | `core/virtualization/src/test/resources/breadcrumb-golden/` |

**硬规则**：探针通过 ≠ 应用可用（v141 Java IO hook 探针 W38 成功，Via 却完全不可交互）。

## 三之二、T-1 / T-2 / T-3（2026-11-28 落地）

| 项 | 内容 | 复用的组件 |
| --- | --- | --- |
| **T-1** | W（WebView）实验的结果并入 `probe-report.json` 的 **`webext` 组**，不再只留在 `wvprobe-result.txt` ⇒ CI 可直接比对 MIME | `Report.put` / `Report.flush`（唯一写盘点） |
| **T-2** | `Report.put` 内**按 id 先删后插**（保留最后一条）。早期窗口那条仍在 `probe-early.json`，证据不丢 | `Report.put`（`ProbeSink` 与 provider 的共同入口） |
| **T-3** | 新增 `H2.lib_allow_applied`：**期望**读 `<instance>/files/lib-allow.json`（容器 bind 时写），**实际**读容器 `debug-trace.log` 的 `hook stats`；期望非空而 `applied==0` ⇒ **fail** | `NativeHookBridge.hookStats()`（Kotlin）；探针侧 `readText`/`lastLineContaining` |

**为什么需要 T-3**：G3 白名单曾因 `prop_contains` 参数方向反了而"以为开了其实没开"，`applied` 停在 1 却无人发现。
T-3 让这个失败形态**在 CI 里红**。

探针项：102 → **103**（`H2`）。
