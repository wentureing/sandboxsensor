# 操作-安装流程（普通安装 / 容器内安装）

> 本轮（2026-11-23）踩过的安装坑都在这里。**两条铁律**：
> 1. **推送/安装后需要用户在手机上点击确认**，期间**不要执行任何操作**
> 2. **容器内安装前必须先确认容器已启动**，装完**核对实例数量**

---

## 一、普通安装（`adb install`）

### 1.1 流程

```powershell
# 0) 确认设备在线
adb devices

# 1) 安装（可能需要手机上点"安装"）
.\tools\install-and-wait.ps1 -Apk dist\container-shitjumpingvm-<sha>.apk
```

`install-and-wait.ps1` 做四步验证，**期间不要并发操作**：

| 步骤 | 内容 |
| --- | --- |
| 1 | `adb install -r`（签名不匹配时自动降级为卸载+重装） |
| 2 | 轮询 `dumpsys package <pkg> lastUpdateTime` **发生变化** |
| 3 | 轮询 `pm path <pkg>` **有输出** |
| 4 | 打印 `versionName` / `lastUpdateTime` |

### 1.2 必须知道的四件事

| # | 事实 | 后果 |
| --- | --- | --- |
| 1 | **安装可能需要用户点击**（`INSTALL` 确认弹窗） | 脚本会等待，**不要在此期间做别的操作** |
| 2 | **签名不一致 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`** | 只能卸载重装，**沙箱数据全丢**（见 `架构-总览.md` §5.5） |
| 3 | **卸载会清掉 `appops` 授权** | 重装后 `MANAGE_EXTERNAL_STORAGE` 又变回 `default`，导入通道失效 |
| 4 | **固定签名 + 递增版本号**后 `install -r` 才能直接覆盖 | 见 workflow 的 `Cache debug keystore` + `versionCode=GITHUB_RUN_NUMBER` |

## 二、容器内安装（`CmdReceiver.INSTALL`）

### 2.1 三个前置检查（**缺一不可**）

```powershell
# ① 容器必须已启动（pidof 必须非空）
adb shell pidof com.nextvm.app

# ② 当前实例数量（决定要不要先卸载）
adb shell run-as com.nextvm.app ls -1 files/virtual/data

# ③ 源 APK 可读
adb shell ls -l /sdcard/Download/x.apk     # 需要 MANAGE_EXTERNAL_STORAGE=allow
adb shell ls -l /data/local/tmp/x.apk      # 无需额外授权
```

**如果 ① 为空** → 先启动容器（`am start -n com.nextvm.app/.MainActivity`），等 `pidof` 有输出再继续。

### 2.2 清理旧实例（每次只删一个）

**⚠️ `uninstallAppByPackage` 只删第一个匹配的实例**（`findAppByPackage` 返回单个），
所以 **N 个实例要调用 N 次**：

```powershell
# 循环直到 data 目录为空
for ($i=1; $i -le 10; $i++) {
    $before = (adb shell "run-as com.nextvm.app ls -1 files/virtual/data") -join ''
    if (-not $before.Trim()) { break }
    adb shell am broadcast -n com.nextvm.app/.CmdReceiver `
        -a com.nextvm.cmd.UNINSTALL --es pkg com.sandbox.probe
    Start-Sleep -Seconds 6      # ← 等它删完，不要并发
}
# 确认：LIST count=0
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LIST
```

**本轮实例**：沙箱里堆了 3 个探针实例（`1795442718610` / `1795443003679` / `1795444295165`），
逐个卸载 3 次才清空。

### 2.3 安装

```powershell
adb shell am broadcast -n com.nextvm.app/.CmdReceiver `
    -a com.nextvm.cmd.INSTALL --es path /sdcard/Download/x.apk
# 等 12 秒（期间不做任何操作）
# 看结果
adb logcat -d -s CmdReceiver | Select-String "INSTALL"
```

成功标志：

```
INSTALL /sdcard/Download/x.apk -> Success(data=VirtualApp(
  packageName=com.sandbox.probe, versionName=1.7, versionCode=8, ...))
```

### 2.4 装后核对（**必须**）

```powershell
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LIST
adb shell run-as com.nextvm.app ls -1 files/virtual/data
```

| 判据 | 期望 |
| --- | --- |
| `LIST count` | **1**（不是 0，也不是 3） |
| `files/virtual/data` | 恰好一个 `<pkg>_<timestamp>` |
| `versionName` / `versionCode` | 与安装包一致 |

### 2.5 启动与验证（**用 `LAUNCH_ACTIVITY`，不要用 `LAUNCH`**）

```powershell
adb shell am broadcast -n com.nextvm.app/.CmdReceiver `
    -a com.nextvm.cmd.LAUNCH_ACTIVITY `
    --es pkg com.sandbox.probe `
    --es activity com.sandbox.probe.UiTestActivity
# 等 15 秒
adb shell pidof com.sandbox.probe
adb logcat -d -b all | Select-String "PROBE.*REPORT v1 part"
```

**判据**：`pidof` 有输出，且 `REPORT 分块` ≥ 10（20 块 = 2 份报告）。

**为什么不用 `LAUNCH`**（实测差异）：

| 命令 | 容器起的 Activity | 表现 |
| --- | --- | --- |
| `LAUNCH` | `mainActivity` = **`ProbeActivity`**（容器取 `activities[0]`，**不解析 LAUNCHER**） | 跑完 `ProbeRunner` 立即 **`finish()`**（`ProbeActivity.java` L45–51）→ **黑屏一闪，没有页面** |
| **`LAUNCH_ACTIVITY ...UiTestActivity`** | `UiTestActivity` | **不 finish、有文字页面**，**也照常跑 `ProbeRunner`** |

**约定**：脚本一律用 `LAUNCH_ACTIVITY` 起 `UiTestActivity` ——
**既有文字页面（人工查看），也照常跑测试（脚本取数据）**。

## 三、本轮踩到的三个坑

### 坑 1：`uninstallAppByPackage` 只删一个

```kotlin
fun uninstallAppByPackage(packageName: String): VmResult<Unit> {
    val app = findAppByPackage(packageName)      // ← 返回单个
        ?: return VmResult.Error("No virtual app found...")
    return uninstallApp(app.instanceId)          // ← 只删这一个
}
```

**后果**：以为"卸载探针"就清空了，实际还剩 2 个。

**避免**：卸载后**必须**用 `run-as ls files/virtual/data` 核对为空。

### 坑 2：`mainActivity` 取 `activities[0]`，不是 LAUNCHER

探针 v1.7 的 LAUNCHER 是 `UiTestActivity`，但容器报：

```
APP pkg=com.sandbox.probe ... main=com.sandbox.probe.ProbeActivity
```

**原因**：容器解析 `mainActivity` 时取 `activities[0]`，不解析 `LAUNCHER` filter。

**后果**：
- `LAUNCH` 会起 `ProbeActivity`（不是 `UiTestActivity`）
- 要起 `UiTestActivity` **必须**用 `LAUNCH_ACTIVITY --es activity com.sandbox.probe.UiTestActivity`

**好消息**：v1.7 的 `ProbeActivity` 也会跑 `ProbeRunner`，所以 `LAUNCH` 不会导致数据缺失。

### 坑 3：安装期间并发操作会打断

**现象**：`am broadcast` 之后立刻 `ls` / `logcat`，拿到的可能是**安装前**的状态。

**避免**：`INSTALL` 后**固定等 10–12 秒**，再用 `LIST` 核对。

## 四、两条路径怎么选

| 场景 | 用哪条 | 条件 |
| --- | --- | --- |
| 装容器 APK 本身 | **普通安装** `install-and-wait.ps1` | 需要用户点击 |
| 装 guest（探针/Via 等） | **容器内安装** `CmdReceiver.INSTALL` | 容器已启动 + 源 APK 可读 |

**源 APK 可读的两条路**：

| 路径 | 条件 | 备注 |
| --- | --- | --- |
| `/sdcard/Download/` | **`MANAGE_EXTERNAL_STORAGE = allow`** | 实测 `default` 时报 `APK file not found` |
| `/data/local/tmp/` | 无需额外授权（644） | 更省事 |

## 五、一条命令速查（装 guest）

```powershell
# 0) 前置
adb shell pidof com.nextvm.app
# 1) 清空旧实例（循环直到空）
while ((adb shell "run-as com.nextvm.app ls files/virtual/data" 2>$null)) {
    adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.UNINSTALL --es pkg com.sandbox.probe
    Start-Sleep 6
}
# 2) 安装
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.INSTALL --es path /sdcard/Download/x.apk
Start-Sleep 12
# 3) 核对
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LIST
adb logcat -d -s CmdReceiver | Select-String "LIST count|APP pkg"
# 4) 启动
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LAUNCH --es pkg com.sandbox.probe
Start-Sleep 15
adb shell pidof com.sandbox.probe
```
