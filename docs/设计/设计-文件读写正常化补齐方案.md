# 设计：让它读写文件正常 —— 完整流程清单

- 日期：2026-11-25
- 背景：方案A 实测失败，暴露的不是"某条规则"，而是**文件操作链整体不完整**
- 目标：给出"guest 读写文件正常"所需的**全部流程**，按必做程度分层，每层可独立验证
- 现状矩阵见 `docs/架构/架构-hook路径覆盖矩阵与缺口.md`

---

## 一、先看清现状：三层各自缺什么

### 1.1 native 层（GOT/PLT patch，作用于应用库）

| 已 hook（8） | 缺失（全部实测确认） |
| --- | --- |
| `open` `openat` `fopen` | **`mkdir` `mkdirat`** ← 目录创建 |
| `access` `stat` `lstat` | **`rename` `renameat`** ← 重命名 |
| `readlink` `opendir` | **`unlink` `unlinkat` `rmdir`** ← 删除 |
| | **`realpath`** ← 路径规范化 |
| | **`statfs` `statvfs`** ← 空间检查 |
| | **`truncate` `ftruncate`** ← 截断 |

### 1.2 Java 层（`JavaIoHooks` → `install_java_io_hooks`）

| 项 | 现状 |
| --- | --- |
| 覆盖 | **只有 `open` 和 `access`** |
| 默认开关 | **关闭**（`DebugFlags.isOn(DebugFlags.JAVA_IO, false)`） |
| `hookFileClass()` | **空实现** —— 注释写"Phase 1 由 VirtualContext 处理"，实际什么都没做 |
| 缺 | `mkdirs` / `delete` / `renameTo` / `getCanonicalPath` / `getUsableSpace` |

### 1.3 前缀重定向（`redirect_path`）

| 特性 | 现状 |
| --- | --- |
| 匹配 | **最长前缀优先**（native + Kotlin 一致）✅ |
| 语义 | **纯前缀替换** —— 不建目录、不保证可写、不处理符号链接 |
| 失败 | **完全静默**（`hooked_open` 直接返回 `real_open` 的结果） |

## 二、必须补的流程（按依赖顺序）

### P1 —— 目录创建链（**没有它，其他都白做**）

| # | 补什么 | 具体做法 | 为什么 |
| --- | --- | --- | --- |
| 1.1 | hook `mkdir` / `mkdirat` | `redirect_path` 后**逐级建父目录**（`mkdir -p` 语义），且**必须直调 `real_mkdir`** 防止递归 | 目前 `mkdir` 落宿主 → 沙箱里目标目录树永远不存在 |
| 1.2 | `hooked_open` 的 ENOENT 兜底 | 写模式（`O_CREAT`）失败且 `errno==ENOENT` 时，`mkdir -p` 重定向后的父目录，**重试一次** | 双保险：某些库用 `open` 而不是 `mkdir` 建目录 |

**完成判据**：
```
via 启动后 <instance>/host_ext/files/offline/ 存在（不是只在宿主存在）
```

### P2 —— 写入 / 重命名链

| # | 补什么 | 为什么 |
| --- | --- | --- |
| 2.1 | hook `rename` / `renameat` | 保存网页常用「写临时文件 → rename 成正式名」；源/目标跨边界时会失败或落宿主 |
| 2.2 | 重定向后**同时确认目标父目录**（复用 1.1 的 `mkdir -p`） | rename 不建目录 |

**完成判据**：临时文件与最终文件都在沙箱；宿主不出现同名文件。

### P3 —— 删除链（**安全红线，不是功能**）

| # | 补什么 | 为什么 |
| --- | --- | --- |
| 3.1 | hook `unlink` / `unlinkat` | **当前 guest 删文件删的是宿主的真实文件** —— 这是数据安全事故，不是功能缺陷 |
| 3.2 | hook `rmdir` | 同上 |

**完成判据**：guest 删除 `.../data/com.nextvm.app/files/xxx` 时，宿主的那个文件**不受影响**。

### P4 —— 路径规范化与空间检查

| # | 补什么 | 为什么 |
| --- | --- | --- |
| 4.1 | hook `realpath` | 返回宿主路径 → 应用拿它当"规范路径"再拼其他路径 → **逃逸放大器** |
| 4.2 | hook `statfs` / `statvfs` | 应用会先检查剩余空间；拿到宿主值可能判定"空间不足"而拒绝保存 |
| 4.3 | hook `truncate` | 覆盖写入前的截断 |

**完成判据**：`realpath` 返回沙箱路径；空间检查数值与实际沙箱一致（或至少不阻碍写入）。

### P5 —— Java 层补齐

| # | 补什么 | 备注 |
| --- | --- | --- |
| 5.1 | 把 `JavaIoHooks` 从 `open`/`access` 扩到 `mkdir`/`rename`/`delete` | 只在 native hook 不可用时兜底；**不默认开启**（v147 教训：开了会把 Via 打成不可交互） |
| 5.2 | `hookFileClass()` 要么实现、要么删掉 | 现在是**空函数 + 误导性注释**，属于"看起来有、实际没有"的架构债 |

## 三、为什么不能只做 P1 就收工

| 只做 P1 会怎样 | 后果 |
| --- | --- |
| 目录能建了、文件能写了 | ✅ 保存/列表正常 |
| 但 `unlink` 未 hook | ❌ **guest 删文件会删到宿主**（比"看不到文件"严重得多） |
| 但 `rename` 未 hook | ⚠️ 保存流程里"临时→正式"那一步可能失败或落宿主 |
| 但 `realpath` 未 hook | ⚠️ 应用拿到宿主规范路径后再次逃逸，P1 的效果被绕过 |

**所以 P1 是"让功能跑通"，P3 是"不破坏宿主"，两者必须一起上。**

## 四、实施顺序与验证矩阵

| 阶段 | 改动 | 独立验证（不依赖 via） |
| --- | --- | --- |
| P1 | `mkdir` hook + `open` 兜底 | 探针：在 guest 里 `mkdir /storage/emulated/0/Android/data/com.nextvm.app/files/t/` → 检查沙箱 `host_ext/files/t` 与宿主**同时** |
| P2 | `rename` hook | 探针：写临时文件 → rename → 检查两侧 |
| P3 | `unlink`/`rmdir` hook | 探针：在宿主预放一个文件 → guest 删除 → 宿主文件**必须还在** |
| P4 | `realpath`/`statfs` | 探针：打印 `realpath` 返回值 |
| P5 | Java 层 | 探针 W38 那套（历史上有过：探针通过但 Via 不可交互 → 必须真机回归） |

**每个阶段都必须有"宿主侧证据"**：只看沙箱有没有文件，不足以证明重定向生效 ——
还要看宿主**有没有多出东西**。

## 五、设计约束（从本轮教训固化）

| # | 约束 | 来源 |
| --- | --- | --- |
| 1 | **重定向前缀 = 目录树根**：加规则时必须保证目标目录存在，或 hook 里自动建 | 方案A 失败 |
| 2 | **`mkdir` 类 hook 必须 `mkdir -p`**，且直调 `real_mkdir` | `mkdir` 不建父目录 |
| 3 | **失败必须可观测**：`hooked_open` 的 ENOENT 应记一条（DebugTrace 或计数器） | 目前完全静默 |
| 4 | **写类 hook 与删类 hook 必须成对上线** | 只 hook 写不 hook 删 → 删到宿主 |
| 5 | **每个 hook 都要有"宿主侧无变化"的断言** | 只看沙箱侧会漏 |

## 六、给 `mkdir` hook 的伪代码（最容易踩坑的一处）

```cpp
// 逐级建目录，全部直调 real_mkdir，绝不经过 redirect_path
static void mkdir_p_real(const std::string& path) {
    for (size_t i = 1; i < path.size(); ++i) {
        if (path[i] == '/') {
            std::string sub = path.substr(0, i);
            real_mkdir(sub.c_str(), 0770);   // 失败忽略（EEXIST 正常）
        }
    }
    real_mkdir(path.c_str(), 0770);
}

static int hooked_mkdir(const char* path, mode_t mode) {
    std::string redirected = redirect_path(path);
    if (redirected.empty()) return real_mkdir(path, mode);
    mkdir_p_real(redirected);        // ← 关键：目标路径逐级建
    return real_mkdir(redirected, mode);
}
```

**两个坑**：
1. `mkdir_p_real` 必须用 `real_mkdir`（用 `mkdir` 会递归进 hook）
2. mode 要带 `S_IWUSR`，否则后续 `open` 写入会 `EACCES`

## 七、一句话

> **让 guest 读写正常 = 目录创建（P1）+ 重命名（P2）+ 删除（P3）+ 路径规范化/空间（P4）+ Java 兜底（P5）。**
> 当前只做了"读"和"部分写"，**目录创建和删除完全缺失** ——
> 前者导致"写了看不到"，后者导致"删到宿主"。
