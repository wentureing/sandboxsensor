# 设计：内容目录的三态与"真假"取舍（2026-11-28）

- 背景：via 主页 `text/plain` 的根因是 **URL 里含宿主包名**。为此有三条可选路线，
  它们在"**guest 看到什么**"和"**WebView 读什么**"上的真假状态完全不同。
- 本文明确三态、选定 B 作为**默认可用态**、A 作为**目标态**，并写清 B 的取舍代价。

---

## 一、三态对照（关键：guest 视角 vs 真实落点）

| 态 | `getFilesDir()` 返回 | guest 看到的是 | 真实落点 | WebView `file://` MIME | 是否泄漏容器包名 |
| --- | --- | --- | --- | --- | --- |
| **S：现状 `SANDBOX_REAL`** | `/data/user/0/com.nextvm.app/files/virtual/data/<inst>/files` | **真路径，但含宿主包名** | 同左（真） | **`text/plain`** ❌ | **是**（`com.nextvm.app` 出现在 guest 的路径里） |
| **A：`SYNTHETIC`** | `/data/user/0/<guest>/files`（合成） | **假路径（真机形状）** | 沙箱（靠 G3/javaIo 翻译） | `text/html` ⚠️ 前提是**读取被翻译**（当前 G3 未完善） | 否 ✅ |
| **B：`EXTERNAL_VISIBLE`** | `/storage/emulated/0/vsandbox/<guest>/files` | **真路径（非真机形状）** | 同左（真） | **`text/html`** ✅（`W-ext-guestpkg` 实测） | 否 ✅ |

**一句话**：

- **A = 假路径（真机形状）+ 真读取（翻译）**
- **B = 真路径（非真机形状）+ 真读取（无需翻译）**
- **S（现状）= 真路径（真机真路径）+ 真读取，但泄漏容器包名 ⇒ MIME 错**

---

## 二、B 的"真假"状态（明确回答）

选 B 后：

| 问题 | 答案 |
| --- | --- |
| guest 拿到的是假路径吗？ | **不是**。`getFilesDir()` 返回 `/storage/emulated/0/vsandbox/<guest>/files`，**真实存在、可直接读写** |
| 那"路径欺骗"还存在吗？ | **退化为"不泄漏容器包名"**：guest 看不到 `com.nextvm.app`，但看到的是一个**真机上不存在的目录形状** |
| 这比现状好还是差？ | **双向改善**：① MIME 从 `text/plain` → `text/html`；② 不再泄漏容器包名。**代价**是形状非真机 |
| 与设计理念（"看起来真实、用起来重定向、骗不过就放弃"）冲突吗？ | **部分偏离**：B 不做重定向（真读），所以"用起来"没问题；但"看起来真实"做不到（`/storage/emulated/0/vsandbox/<pkg>/` 不是任何真机 app 的私有目录形状） |
| 会影响目标 4（深入欺骗）吗？ | **会**：形状本身是检测面。所以 B 是**可用性优先的临时态**，不是欺骗完整态 |

---

## 三、决策：三态共存，B 为默认，A 为目标

```
ContentRootMode = { SANDBOX_REAL, SYNTHETIC, EXTERNAL_VISIBLE }
                   现状(默认回退)   A(目标态)      B(默认可用态)
```

| 决策 | 内容 |
| --- | --- |
| **默认** | `EXTERNAL_VISIBLE`（B）—— 优先让 via 主页正常 |
| **回退** | `SANDBOX_REAL`（现状）—— 一键回到今天的行为 |
| **目标** | `SYNTHETIC`（A）—— 等 G3 完善（最小一致集 + 崩溃机制）后切过去，届时形状与欺骗性最佳 |
| **切换粒度** | **按 guest**，由 `PathSpoofConfig` 的 **[内容目录外部化名单]**（`path_spoof.conf` 的 `[内容目录外部化名单]` 节）控制；默认只含 `mark.via`；运行时 `CONTENT_ROOT_ADD/REMOVE/LIST` 增删 |
| **只作用于内容目录** | `files/cache/external_files` 这一类"内容目录"；`databases/code_cache/lib` **仍留内部**（避免 SQLite/dex 语义破坏） |

**为什么三态共存而不是二选一**：

1. B 能**立刻交付**目标 1 的 WebView 部分（判据已由 `W-ext-guestpkg` 实测拿到：`text/html`）；
2. A 需要 G3 完善（当前崩溃机制未定），**不能阻塞** B；
3. 三态共享同一个"内容目录"抽象，切换只改一个枚举，**回退成本最低**。

## 四、B 的实现影响面（~40 行）

| 文件 | 改动 |
| --- | --- |
| `PathKinds.kt` | 给 `FILES/CACHE/EXTERNAL_*` 族加"`EXTERNAL_VISIBLE` 形态"（`synthetic` 按模式返回 vsandbox 路径），不新增族 |
| `VirtualContext`（`getFilesDir` 等 14 个 getter） | 按 `ContentRootMode` 返回不同根 |
| `GuestPathSetup` / `VAM` | 建目录（`/storage/emulated/0/vsandbox/<guest>/files`）+ 写 `.nomedia` + 注册规则（B 下**不需要翻译规则**，但 `DATA_ROOT` 旧规则保留给 A） |
| `DebugFlags` | `contentRoot` 开关（默认 `external_visible`） |
| 风险 | `getFilesDir()` 返回外部路径：① 个别 app 假设 `/data/` 前缀；② 清理/卸载需删外部目录；③ 多实例需按 instance 分子目录 |

**判据**：

| 项 | 期望 |
| --- | --- |
| via 主页 `document.contentType` | **`text/html`** 且正常渲染 |
| guest 路径不含 `com.nextvm.app` | 是 |
| `getFilesDir()` 可读写 | 是（`W-ext-guestpkg` 已证同目录可读） |
| 数据库/代码缓存 | 仍在内部（`databases/`、`code_cache/` 不受影响） |
| 回退 | `contentRoot=sandbox` → 行为与今天完全一致 |

## 五、与"guest 假路径 + WebView 真读"（A）的关系

| 项 | A（原设计） | B（本次采用） |
| --- | --- | --- |
| guest 视角 | 假路径（真机形状） | 真路径（非真机形状） |
| WebView 读取 | 需翻译（G3） | 无需翻译 |
| MIME | `text/html`（前提：翻译成功） | `text/html`（已实测） |
| 欺骗性 | 高（形状真机） | 低（形状非真机） |
| 当前可行 | ❌ G3 未完善（单库崩、全量性能/检测面） | ✅ 立即可用 |

**结论**：B **不是** A 的替代，而是 A 的**前置可用态**。A 的价值（真机形状）在目标 4（深入欺骗）时才必须；
在那之前，B 用最小代价解决目标 1。
