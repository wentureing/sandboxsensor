# docs/ 索引

> **先读 `../STATUS.md` 看当前状态。** 本文件只说明**文档放在哪、每类解决什么问题**。
>
> 结构（2026-11-24 重组：五类独立目录 + 错误结论归档）：
> ```
> docs/
> ├── README.md        ← 本文件（总索引）
> ├── 计划/            ← 要做什么、按什么顺序做
> ├── 架构/            ← 系统怎么运作（机制/原理/边界）
> ├── 设计/            ← 为什么这样设计（选型、路线取舍、规范）
> ├── 现状/            ← 现在是什么样（索引、零调用扫描等事实快照）
> ├── 输出/            ← 做过什么（实验记录、变更、调研、调试工具、操作手册）
> ├── archive/         ← **错误结论归档**（结论已被实测推翻，禁止当依据）
> └── diagrams/        ← 图表源码
> ```

---

## 一、五个目录怎么分工

| 目录 | 回答的问题 | 什么时候读 |
| --- | --- | --- |
| **计划/** | 「接下来做什么」 | 开工前定任务、看优先级、看已完成项 |
| **架构/** | 「它怎么运作」 | 改代码前必须读，避免基于错误假设动手 |
| **设计/** | 「为什么这么选」 | 要推翻/延续某个设计决策时 |
| **现状/** | 「现在是什么样」 | 判断某项能力是否真的生效（零调用扫描） |
| **输出/** | 「做过什么、证据在哪」 | 复盘、找实测数据、查变更 diff |
| **archive/** | 「哪些结论是错的」 | **引用任何结论前对照一遍** |

## 三、写作约定（与 `../AGENTS.md` 一致）

| 类型 | 放哪 | 命名 |
| --- | --- | --- |
| 计划（要做什么） | `计划/` | `计划-<主题>.md` / `P<优先级>-<序号>-<主题>.md` |
| 架构（怎么运作） | `架构/` | `架构-<主题>.md` |
| 设计（为什么这么选） | `设计/` | `设计-<主题>.md` / `调查-<主题>.md` |
| 现状快照 | `现状/` | `<主题>.md` |
| 实验记录 | `输出/记录/` | `记录-<主题>.md` |
| 变更计划与实际 diff | `输出/变更/` | `<YYYYMMDD>-<任务>.md` + `.actual.diff` |
| 调研（选型/逆向） | `输出/调研/` | `调查-*.md` / `调研-*.md` |

**硬性要求**：
1. 结论必须带**实测证据**（探针编号 / logcat 片段 / 反汇编结果），不能只有推理
2. 被推翻的结论**不删**，移到 `archive/错误结论-<年月>/` 并在其 README 登记
3. 文档里引用别的文档用**相对路径**；本次重组后旧路径（`docs/records/`、`docs/changes/`、`docs/调研/`）已不存在
4. 一份文档只回答一个问题；跨主题就拆
