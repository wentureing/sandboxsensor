## 六、C++（churn 第一）没有自动化的对策

| 选项 | 成本 | 评价 |
| --- | --- | --- |
| A. 把 `redirect_path` / `is_path_hidden` / `trim_trailing_slashes` 抽到无 JNI 的头文件，CI 用 g++ 跑向量 | 中（要动 7 468 行文件的结构） | **推荐**，但要和 B2 拆包一起做，避免两次动刀 |
| B. 真机自检：debug 开关启动时跑一组 `(rule,path,expect)` 向量写 `debug-trace` | 低 | 可立刻做；缺点是"要装包才知道" |
| C. Kotlin 复刻 C++ 逻辑对拍 | 低 | ❌ 等于再造一份实现，违背"不重复实现" |

**当前结论**：先 C++ 与 Java 的**语义同步靠同一次提交 + 同一份变更文档**（`11f23d5` 就是这么做的）；
A/B 二选一留到 B2 拆包时决定。

## 七、本轮已发现并修复的真缺陷

`removeAppRedirections` **与 `setupAppRedirections` 不对称**：注册 16 条，删除只写死 5 条前缀 →
`media` 规则、obb/external 的无尾斜杠变体、宿主包名兜底共 **11 条会残留**。
残留的后果：guest 卸载/停止后这些规则仍把路径往它的沙箱翻译（若同一进程启动另一个 guest，会串）。

修法：删除改为按 `PathKinds` 的 APP 族 + `hostFallbackForms` **派生 key**，与注册共用同一份数据
（同时消掉"手写清单"这处重复）。测试 `R8` 钉住"删除后不残留本包任何规则"。
