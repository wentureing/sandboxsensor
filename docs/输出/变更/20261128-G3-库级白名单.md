# 变更：G3 库级白名单（pkg 优先，符号受限）2026-11-28

## 目标

让 `libjavacore.so`（以及可选的 `libmonochrome_64.so`）在**指定 guest** 内被 GOT patch，
但**只 patch 5 个符号**（`open/openat/stat/access/readlink`），从而让"guest 合成路径"的读写都被翻译。

## 背景（取证结论）

| 证据 | 结论 |
| --- | --- |
| `webview-read.log`（`openDiag=1`，24 条） | 读取者 = **`libjavacore.so`（22 条）** + `libmonochrome_64.so`（2 条），全部在**容器进程**内 |
| `W-ext-synthpath` 合成路径 `open` 成功（`err=0`） | `PathKinds.DATA_ROOT` 规则早已覆盖 `/data/user/0/<guest>/` → `<instanceDir>` |
| `synthpath` 仍 `about:blank` | `File.exists()` 走 `stat`，诊断模式只 patch 了 `open/openat` |
| 全量 50 库 patch | `W-big`（8 MB）**超时 8 s** ⇒ 不能全量，必须按库白名单 |

## 影响范围

| 文件 | 改动 |
| --- | --- |
| `core/hook/src/main/cpp/native-hook.cpp` | 新增 `prop_contains` / `prop_list_exact` / `ns_lib_allow_hit` / `ns_allow_symbol`；
过滤处放行白名单库；符号过滤扩展为"白名单库只 patch 允许符号" |

## 配置（系统属性，逗号分隔；**pkg 优先于 lib**）

```
debug.nextvm.pkgAllow = mark.via,com.sandbox.probe
debug.nextvm.libAllow = libjavacore,libmonochrome_64
debug.nextvm.symAllow = open,openat,stat,access,readlink
```

**决策顺序**（与 `计划-GOT白名单黑名单与WebView.md` §二 一致）：

```
pkg ∉ pkgAllow              → 完全走原逻辑（系统库照旧跳过）
pkg ∈ pkgAllow 且 lib ∈ libAllow:
    → 即使 classify 判为系统库也 patch
    → 但只 patch symAllow 里的符号（精确逗号匹配，避免 open ⊂ openat 误命中）
lib ∈ libAllow 但 pkg ∉ pkgAllow → 不生效（白名单作用域限定）
```

## 风险

| 风险 | 对策 |
| --- | --- |
| patch `libjavacore.so` 影响所有 Java I/O 性能 | 只 5 个符号；`redirect_path` 是前缀比较（纳秒级）；`wv_read_trace` 只在 `openDiag` 时写文件 |
| patch `libmonochrome_64.so`（Chromium）不稳 | 先只开 `libjavacore`；确认合成路径可读后再加 monochrome |
| 属性未设置时零影响 | `ns_lib_allow_hit` 读不到属性即返回 false ⇒ 完全等价旧行为 |

## 回退

```powershell
adb shell "setprop debug.nextvm.pkgAllow ''"
adb shell "setprop debug.nextvm.libAllow ''"
adb shell "setprop debug.nextvm.symAllow ''"
adb shell "am force-stop com.nextvm.app; am start -n com.nextvm.app/.MainActivity"
```

## 验证方法

```powershell
adb shell "setprop debug.nextvm.pkgAllow mark.via,com.sandbox.probe"
adb shell "setprop debug.nextvm.libAllow libjavacore"
adb shell "setprop debug.nextvm.symAllow open,openat,stat,access,readlink"
adb shell "setprop debug.nextvm.openDiag ''"   # 关诊断，避免全量 patch
# 重启容器（等 10s）→ 起 WebViewProbeActivity
adb shell run-as com.nextvm.app grep -aE 'W-ext-synthpath|W2 url=' files/virtual/data/<inst>/files/wvprobe-result.txt
adb shell run-as com.nextvm.app grep -a 'hook stats' files/debug-trace.log | tail -2
```

| 判据 | 期望 |
| --- | --- |
| `hook stats` | `applied` ≈ 1–2（只有 libjavacore），**不是 50** |
| `W-ext-synthpath` | `text/html` **且 body 是 `WVPAGE_OK`**（不再 `about:blank`/`EMPTY`） |
| `W2` | 仍 `text/plain`（宿主包名触发嗅探，属独立问题） |
| `W-big` | 不超时 |
| via | 不受影响（`pkgAllow` 只影响列出的包） |
