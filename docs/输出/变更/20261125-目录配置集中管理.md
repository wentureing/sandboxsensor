## 三、数据设计（关键决策）

```kotlin
class PathKindSpec(
    val kind: PathKind,
    val owner: RedirectOwner,                       // 哪个 setup* 入口注册（冲突 2）
    val synthetic: (pkg: String, type: String?) -> String,
    val sandboxRel: ((pkg: String, type: String?) -> String)?,  // null = 调用方给绝对路径（APK）
    val hostForms: (pkg: String) -> List<String>,   // 含/不含尾斜杠两种（冲突 3）
    val coveredBy: PathKind?,                       // 非空 = 自己不注册，由父族前缀覆盖
)
```

| 族 | hostForms 条数 | coveredBy | owner |
| --- | --- | --- | --- |
| DATA_ROOT | 2（`/data/data/<pkg>/`、`/data/user/0/<pkg>/`） | — | APP |
| FILES / CACHE / CODE_CACHE / NO_BACKUP / DATABASES / APP_DIR | 0 | DATA_ROOT | APP |
| EXTERNAL_DATA | 4（A/B × 含/不含尾斜杠） | — | APP |
| EXTERNAL_FILES / EXTERNAL_CACHE | 0 | EXTERNAL_DATA | APP |
| OBB / MEDIA | 4 | — | APP |
| APK | 1（精确路径） | — | PATH_FIDELITY |
| NATIVE_LIB | 1（带尾斜杠） | — | PATH_FIDELITY |

**规则数核算**：APP = 2 + 4 + 4 + 4 = **14**；PATH_FIDELITY = **2**；宿主包名兜底另由 `hostFallbackRules()` 给 **2** → 合计 **18**，
与现有 `setupAppRedirections`(16) + `setupPathFidelityRedirections`(+2) 对齐（16 = 14 + 2 兜底）。

用户要求（2026-11-25）：via 不执行目录欺骗但写入要导沙箱；via 放在**可配置白名单**而非写死；
并且"白名单是否生效"必须有自动化测试。

### 8.2 为什么这样测（而不是 Robolectric）

`core:sandbox` 虽有 Robolectric，但 `RobolectricSmokeTest` 因 `android-all-instrumented`（~100 MB）
在 CI 下载不稳定而被 `@Ignore`。所以"白名单生效"的验证必须走**纯 JVM**：
把 `VirtualContext` 的判据抽成一个包级纯函数（同文件，`internal`），
测试直接打**真实调用链上的三个既有 API**，不新建决策层：

```
path_spoof.conf（豁免/欺骗两份名单）
  → VirtualConstants.isPathFidelityGuest(pkg)          ← 现成的唯一策略入口
  → shouldUseSyntheticContent(pathFidelity, useReal)   ← 现成的唯一内容目录判据
  → PathPolicy.isRedirectionEnabled + PathKinds.rulesFor  ← 现成的隔离契约
```

### 8.3 判据

| 项 | 判据 |
| --- | --- |
| 名单生效 | 改 `path_spoof.conf` → `isPathFidelityGuest` 立即翻转（`W3`） |
| 豁免优先级 | 同时进两份名单 → 不合成（`W5`） |
| 写入仍落沙箱 | 任何名单下 APP 规则都是 14 条且目标全在沙箱内（`W7`） |
| 代码里不写死 via | `PATH_FIDELITY_WHITELIST` 只剩 `CM_PACKAGE`；via 只出现在 `DEFAULT_EXEMPT_PKG`（模板种子）与配置文件的运行态里 |
| 日志 | 数据/策略层不写日志；`VirtualContext` 仍只用 `DebugTrace`（debug 才进产物） |
