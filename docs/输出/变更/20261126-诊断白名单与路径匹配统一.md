## 三、关键设计

### 3.1 `diag_channels.tsv`（共享区 + 差异区）

```
# section  marker  note
shared      debug-trace.log
shared      checks.log
shared      seccomp-diag.log
shared      breadcrumb-
...
kotlin      stateprobe-        只 Kotlin 产，C++ 仍须识别
kotlin      v139-probe.log
cpp         -hooklog-          只 C++ 产（预留，Kotlin 不判）
```

下发/识别规则：

| 消费者 | 使用哪些段 |
| --- | --- |
| C++ `is_container_diag_path` | `shared + kotlin + cpp` |
| Kotlin `DiagFiles.markers()`（下发给 C++） | `shared + kotlin + cpp` |
| Kotlin 自用"是否诊断文件"（如 `DiagFiles.isDiag(name)`） | `shared + kotlin` |

### 3.2 `PathPattern` 语义（两端逐字一致）

| 形态 | 判定 | 有效长度 | 例子 |
| --- | --- | --- | --- |
| `EXACT` | `path == text` | `text.length` | `/system/bin/su` |
| `PREFIX` | `text` 以 `/` 结尾时，`path.startsWith(text)`；另支持"根形态"（`text` 去掉尾 `/` == `path`） | `text.length` | `/data/user/0/com.a/` |
| `GLOB` | 含 `*`；`*` 匹配任意字符序列（含 `/`） | `text.length` | `/data/user/0/*/files` |

选择规则与现状一致：**有效长度最长者胜；平局时真正的前缀优先**。实现放在 `matches()` + `effectiveLength()`，
`PathRuleStore.translate` 与 C++ `redirect_path` 都用它，保证两端同构。

### 3.3 为什么不用 `std::regex`

- NDK 上 `<regex>` 会显著增大 `.so` 且回溯性能不可控，热路径（每次 `open`）不能接受；
- 现有规则 100% 是前缀，正则只对"少数族"有价值 → 用 `GLOB`（`*`）覆盖同样的诉求，语义简单、两端可实现一致；
- 后续若确实需要正则，`PatternKind` 已留枚举位，加一个 `REGEX` 分支并只在**非热路径**（配置解析期）编译。

## 四、风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | 路径匹配改动破坏 guest（历史：Via 不可交互） | golden 向量逐条比对；Kotlin/C++ 同一份 TSV；真机装包回归 Via |
| 2 | 读 resource 在 Android 运行时失败 | `markers()` 读不到时回退内置数组（等价现状），并记一条 `DebugTrace` |
| 3 | `.inc` 与 TSV 漂移 | `gen-diag-channels.mjs --check` 进 CI |
| 4 | `GLOB` 让 `*` 语义误伤（如 `/sdcard` 下有 `*` 的规则过宽） | 现有规则不加 `*`；只在 golden 里用独立 rule_set 验证，不注册到生产表 |
