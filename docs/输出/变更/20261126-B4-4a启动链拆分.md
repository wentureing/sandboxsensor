## 一、目标

把 `VirtualApplicationManager.kt`（2 350 行，2493 总行）里两个**叶子职责**搬到新包
`lifecycle/startup/`，VAM 只留薄委托（"组合与协调"）：

| # | 职责 | 现状 | 去向 |
| --- | --- | --- | --- |
| ① | **怎么造出 Application 实例**（AppComponentFactory → 反射 → 回退 base Application） | `createApplication`（50 行）+ `createViaAppComponentFactory`（17 行） | `startup/GuestApplicationFactory.kt` |
| ② | **按 AOSP 顺序装 ContentProvider**（跳过 Shizuku、四种异常吞掉、注册到 AMS 代理） | `initContentProviders`（92 行） | `startup/ContentProviderInitializer.kt` |

**为什么选这两个**：它们依赖最少（①只依赖 `AndroidCompat`/`runSafe`/`findMethod`；②只依赖 `applications[instanceId]`
一个私有状态），且**优先搬叶子、后搬编排**（编排 `bindApplication` 留给 B4-4b），这样每批都可独立验证。

**不搬**（留给 B4-4b）：`bindApplication`（编排）、`bindViaFrameworkLoadedApk`（框架路径）、
`attachBaseContext`、`patchLoadedApkApplication`、`registerGuestRedirections`、`patchFrameworkDataDir`。

## 三、逐文件改动预览

### 3.1 `GuestApplicationFactory.kt`（新）

```kotlin
object GuestApplicationFactory {
    private const val TAG = "VAppLifecycle"          // 与 VAM 同 tag，日志归属不变

    /** className 为空 = AOSP 的默认 Application。 */
    fun classNameOf(applicationClassName: String?): String =
        applicationClassName ?: "android.app.Application"

    fun create(packageName: String, className: String, classLoader: ClassLoader): Application?  // 原 createApplication 的 try 块
    private fun viaAppComponentFactory(className: String, classLoader: ClassLoader): Application?  // 原 createViaAppComponentFactory

```

搬运要点：**六条日志逐字不变**（`Creating Application` / `created via AppComponentFactory` /
`created via reflection` / `class not found … falling back` / `Failed to create fallback Application` /
`Failed to create Application`），三条降级路径顺序不变（P+ 先工厂 → 反射 → `ClassNotFoundException` 回退 base）。

### 3.2 `ContentProviderInitializer.kt`（新）

```kotlin
object ContentProviderInitializer {
    private const val TAG = "VAppLifecycle"

    /** 需要跳过的 provider（容器原理决定：跨用户权限拿不到）。 */

    fun install(
        instanceId: String,
        providers: List<String>,
        authorities: Map<String, String>,
        classLoader: ClassLoader,
        virtualContext: Context,
        application: Application,
        providerMetaData: Map<String, Bundle> = emptyMap(),

```

搬运要点：provider 循环顺序、`GuestBreadcrumb` 五条文案、四种异常（`ClassNotFoundException` /
`SecurityException` / `IllegalStateException` / `Exception`）的吞法与日志**全部逐字不变**；
`ActivityManagerProxy.activeInstance?.registerVirtualProvider(...)` 位置不变。

### 与计划的 3 处偏差（都已改进实现）

| 原计划 | 实际 | 原因 |
| --- | --- | --- |
| `onInstalled: (ContentProvider) -> Unit = {}` 回调 | `installedInto: MutableList<ContentProvider>? = null` | ① 函数类型的 `->` 破坏 `check-refactor-equivalence.mjs` 的花括号/尖括号配对（实测提取失败）；② `= {}` 默认值会被误判成函数体起点。用列表反而**更贴近原实现**（`record?.contentProviders?.add(provider)`） |
| 私有函数改名 `viaAppComponentFactory` | **保持原名** `createViaAppComponentFactory` | 搬家不改名：改名会让等价检查只剩"人工判断"，保留原名换来**逐字等价**的机器证明 |
| 计划里写"六条日志" | 实际 6 条全部逐字保留（tag 仍 `VAppLifecycle`） | 无变化 |
