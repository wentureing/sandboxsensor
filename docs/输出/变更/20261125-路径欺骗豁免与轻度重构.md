## 一、目标（两条，分开验收）

### 目标 A：路径欺骗豁免机制

给 guest 一个**最高优先级的豁免开关**：在豁免名单里的包，**不做任何路径形态欺骗**
（不用 `synthetic*` 合成路径），但仍然**保留沙箱隔离**（I/O 仍落在容器私有目录）。

- 名单持久化在容器私有目录，**CmdReceiver 可增删查**
- **不要求实时生效**（改完重启容器/guest 生效）

### 目标 B：路径转换轻度重构

按重复代码调查的结论做**结构性收敛**，要求：

1. **数据流与控制流隔离** —— 表只放数据（模板/前缀/相对位置），控制流（`ensureDir`、
   注册时机、反射）留在各自消费方
2. **真假路径分开并分类** —— 每个"路径族"显式区分「合成形态」与「沙箱形态」
3. **每种 hook 可带自己的偏好** —— 每个路径族可单独开关（`PathPolicy.isEnabled(kind)`）
4. **完整、模块化**，**暂不以减少代码为目标**

## 二、关键设计决策（先定这两个，其余都是实现细节）

### 决策 1：豁免 = 关闭"欺骗"，**不**关闭"隔离"

这是整份计划最容易做错的地方。

| 概念 | 含义 | 豁免后 |
| --- | --- | --- |
| **路径形态欺骗** | 让 guest 看到 `/data/user/0/<pkg>` 这类**假路径**（`synthetic*`） | **关闭** |
| **沙箱隔离** | 把 guest 的 I/O 送到 `<containerDataDir>/files/virtual/data/<inst>/` | **保留** |

**为什么隔离必须保留**：如果连 `setupExternalStorageRedirections`（`/sdcard/` → 沙箱）也关掉，
guest 会**直接读写真宿主 `/sdcard`** —— 那是数据污染，不是"豁免欺骗"，是"取消容器"。

**所以豁免的准确语义**：

```
豁免后：
  getFilesDir()       -> <containerDataDir>/.../data/<inst>/files      （真沙箱路径，不合成）
  getDataDir()        -> <containerDataDir>/.../data/<inst>            （真沙箱路径，不合成）
  ApplicationInfo.dataDir -> 同上
  规则表               -> 仍然注册（保证 I/O 落在沙箱），但 guest 自己拼的宿主路径照样被翻译
```

**用户原话「不执行任何路径欺骗」→ 实现为「不产生任何合成路径」**，而不是「不注册任何规则」。

### 决策 2：数据 / 控制流的分界

| 层 | 内容 | 位置 |
| --- | --- | --- |
| **数据** | 路径族清单 + 每族的（合成模板、沙箱相对位置、宿主前缀变体） | `PathKinds.kt`（纯数据） |
| **控制流** | 「谁在什么时候用」「要不要先建目录」「注册顺序」「反射」 | 留在原处（`VirtualContext` / `PackageManagerProxy` / `NativeHookBridge`） |

**表只回答"这个族的三种形态长什么样"，不回答"谁什么时候用它"。**

## 四、逐文件改动预览

### 4.1 `PathKinds.kt`（新增，纯数据）

```kotlin
enum class PathKind {
    DATA_ROOT, FILES, CACHE, CODE_CACHE, NO_BACKUP, DATABASES, APP_DIR,
    EXTERNAL_DATA, EXTERNAL_FILES, EXTERNAL_CACHE, OBB, MEDIA,
    APK, NATIVE_LIB,
}

/**
 * 一个路径族的三种形态。**只有数据，没有控制流。**
 *   synthetic   真机上的样子（豁免/关闭欺骗时不用）
 *   sandboxRel  相对 <instanceDir> 的位置
 *   hostForms   需要被翻译的宿主前缀（含/不含尾斜杠两种都写）
 */
class PathKindSpec(
    val kind: PathKind,
    val synthetic: (pkg: String, type: String?) -> String,
    val sandboxRel: (pkg: String, type: String?) -> String,
    val hostForms: (pkg: String) -> List<String>,
    val defaultEnabled: Boolean = true,
)

object PathKinds {
    val ALL: List<PathKindSpec> = listOf(
        PathKindSpec(
            kind = PathKind.FILES,
            synthetic = { pkg, _ -> "/data/user/0/$pkg/files" },
            sandboxRel = { _, _ -> "files" },
            hostForms = { pkg -> listOf("/data/user/0/$pkg/files", "/data/data/$pkg/files") },
        ),
        // ... 其余 13 个
    )
    fun of(kind: PathKind): PathKindSpec = ALL.first { it.kind == kind }
}
```

### 4.2 `PathSpoofConfig.kt`（新增，持久化）

配置文件位置：`<containerDataDir>/files/path_spoof.conf`

格式（行式，便于手改）：

```
# 豁免名单：这些包不产生任何合成路径（但仍隔离到沙箱）
exempt=mark.via

# 每个路径族的开关（缺省=on）
kind.FILES=off
kind.EXTERNAL_FILES=on
```

API：

```kotlin
object PathSpoofConfig {
    fun load(dir: File)
    fun isGuestExempt(pkg: String): Boolean
    fun setGuestExempt(pkg: String, exempt: Boolean)   // 写文件
    fun exemptList(): List<String>
    fun isKindEnabled(kind: PathKind): Boolean
    fun setKindEnabled(kind: PathKind, enabled: Boolean)
}
```

**不实时生效**：`load()` 在 `initNativeHooks` / guest bind 时调用一次；
`setXxx` 只写文件，生效要重启。

### 4.3 `PathPolicy.kt`（新增，控制流）

```kotlin
object PathPolicy {
    /** 该 guest 是否完全豁免路径欺骗（最高优先级） */
    fun isGuestExempt(pkg: String): Boolean = PathSpoofConfig.isGuestExempt(pkg)

    /** 某个路径族在该 guest 上是否启用合成路径 */
    fun isSpoofEnabled(kind: PathKind, pkg: String): Boolean {
        if (isGuestExempt(pkg)) return false          // 豁免最高优先级
        if (!PathSpoofConfig.isKindEnabled(kind)) return false
        return VirtualConstants.isPathFidelityGuest(pkg)   // 原有白名单
    }
}
```

### 4.4 `VirtualContext.kt`（修改，**只换判断，不动控制流**）

```kotlin
// 改前
override fun getExternalCacheDir(): File {
    val sandboxDir = sandboxManager.getExternalAppCacheDir(instanceId, guestPackageName)
    return contentDir(sandboxDir) { File(VirtualConstants.syntheticExternalCacheDir(guestPackageName)) }
}

// 改后（ensureDir 与返回逻辑原样，只把"要不要合成"换成查 policy）
override fun getExternalCacheDir(): File {
    val sandboxDir = sandboxManager.getExternalAppCacheDir(instanceId, guestPackageName)   // 控制流保留
    return if (PathPolicy.isSpoofEnabled(PathKind.EXTERNAL_CACHE, guestPackageName))
        File(SyntheticPathProvider.get(PathKind.EXTERNAL_CACHE, guestPackageName))
    else sandboxDir
}
```

**移除 `pathFidelity` / `contentPathsUseReal` 两个字段**，统一到 `PathPolicy`。

### 4.5 `NativeHookBridge.kt`（修改）

```kotlin
// 改前：20+ 条手写 addPathRedirection
// 改后：遍历数据表，注册动作留在这里
private fun registerKindSpecs(pkg: String, instanceDir: String) {
    for (spec in PathKinds.ALL) {
        // APK / NATIVE_LIB 只在 pathFidelity 下注册（保持上游分工）
        if (spec.kind in setOf(PathKind.APK, PathKind.NATIVE_LIB) && !PathPolicy.isSpoofEnabled(spec.kind, pkg)) continue
        val target = instanceDir + "/" + spec.sandboxRel(pkg, null) + "/"
        for (h in spec.hostForms(pkg)) {
            addPathRedirection(h, target)     // 控制流：注册动作留在本文件
        }
    }
}
```

## 五、风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| **1** | **规则重写导致规则表变化** → 影响所有 guest 的文件访问 | **硬验证**：改造前后各导一次 `getPathRedirectSnapshot()`，**diff 必须为空**（对应规则 10） |
| **2** | 豁免后 guest 的 `getDataDir()` 变成真沙箱路径 → **反双开检测可能挂** | 这是豁免的**预期语义**（用户明确要求"不执行任何欺骗"）；用 via 验证 |
| **3** | 移除 `pathFidelity` / `contentPathsUseReal` 两个字段 → 影响 13 处 | 逐处替换，`kotlin-lint --deps` 检查；编译期即可发现遗漏 |
| **4** | `PathSpoofConfig` 读写文件失败 → 所有 guest 都豁免或都不豁免 | `load()` 失败时**回落到当前硬编码默认**（`PATH_FIDELITY_WHITELIST`） |
| **5** | `CmdReceiver` 新增命令与现有命令冲突 | 前缀用 `com.nextvm.cmd.SPOOF_*`，不与现有重叠 |

## 六、回退方案

| 阶段 | 回退命令 |
| --- | --- |
| A（豁免机制）完成后出问题 | `git -C _ref/ShitJumpingVM revert <A 的 commit>` |
| B（重构）完成后规则变化 | `git -C _ref/ShitJumpingVM revert <B 的 commit>`；或直接用 snapshot diff 定位 |
| 整体回退到本轮之前 | `git -C _ref/ShitJumpingVM reset --hard 438eab2` |

**A 与 B 分开提交**，A 只加机制（默认行为不变），B 才动规则生成 —— **这样 A 出问题不影响现有行为**。

## 九、待确认的三个问题

1. **豁免后是否连 `getDataDir()` 也返回真路径？**
   我倾向 **是**（用户说"不执行任何路径欺骗"）。但这会让 via 的 `getDataDir()` 暴露沙箱，
   且 `getFilesDir().getParentFile() == getDataDir()` 会**重新成立**（反而更自洽）。

2. **豁免后是否保留 `setupExternalStorageRedirections`（`/sdcard/` → 沙箱）？**
   我倾向 **保留**（那是隔离，不是欺骗）。若也关掉，guest 会读写真宿主 `/sdcard`。

3. **配置文件格式**：行式 `key=value`（便于手改 + CmdReceiver 写）还是 JSON？
   我倾向 **行式**（无依赖、手改友好、写入简单）。
