# 变更：族根匹配语义（ROOT_FORM）—— 让合成路径的「根」可被翻译

- 日期：2026-11-25
- 状态：**已合入并验证**（容器 `11f23d5` + `031eba8`；CI `45579005086` 63 tests 全绿）
- 性质：**匹配语义补充**，不新增规则、不改数据表
- 依据：`docs/输出/记录/记录-T39-T41-族根路径无规则.md`（方案 A）

---

## 一、目标

`VirtualConstants.syntheticDataDir(pkg)` = `/data/user/0/<pkg>`（**无尾斜杠**），
而规则注册的是带尾斜杠的前缀 `/data/user/0/<pkg>/` → `startsWith` 不成立 → 根路径不被翻译。

**修法（方案 A）**：把「等于某条带斜杠规则去掉尾斜杠」并入匹配语义（`ROOT_FORM`）。

| 不做什么 | 为什么 |
| --- | --- |
| 不加无斜杠前缀规则 | `/data/user/0/mark.via` 当前缀会吃掉兄弟包 `mark.via.pro`（T15 守着） |
| 不改 `syntheticDataDir` | AOSP 的 `getDataDir()` 就是无尾斜杠，改了是**新的**欺骗偏差 |
| 不改规则集合 | `getPathRedirectSnapshot()` 必须保持可用作 B 阶段的 diff 判据 |

## 三、语义（写进代码与镜像文档）

| 输入形态 | 命中条件 | 有效长度 | 返回 |
| --- | --- | --- | --- |
| 前缀 | `path.startsWith(from)` | `from.length` | 现有拼接逻辑（`rest` 空时原样返回 `to`，T9 守住） |
| **族根** | `from` 以 `/` 结尾 且 `path == from.dropLast(1)` | `from.length - 1` | `to.trimEnd('/')` |
| 平局 | 有效长度相同 | — | **前缀优先**（更明确的声明胜） |

**为什么有效长度要减 1**：否则 `/sdcard/` 的族根会被更短的前缀抢走或反之，最长匹配失去意义。

## 四、风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| 1 | Java 改了、C++ 没改 → Java 层 `exists()` 成功而 native `open()` 失败 | 同提交改两处；真机回归看 `Dbg/path` 与 `open: A -> B` 两侧 |
| 2 | 兄弟包串味（`mark.via` vs `mark.via.pro`） | 长度必须恰为 `from.length - 1`；T42 守住 |

| 5 | 规则集合变化 | **不变**（只改匹配语义），`getPathRedirectSnapshot()` diff 仍为空 |
