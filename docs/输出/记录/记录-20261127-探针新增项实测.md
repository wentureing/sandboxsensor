### 2.2 `H1.dlsym_bypass` —— **暴露我们自己的判据缺陷**（假阳性）

同一进程两轮结果矛盾：

```
第 1 轮: not-translated errno=2  -> GOT patch 不覆盖 dlsym（预期）
第 2 轮: translated fd>=0 target=/data/data/com.nextvm.app/files/native_dlsym.txt
```

**根因**：第 2 轮的 `dataDir` 已经变成**容器真实路径** `/data/data/com.nextvm.app/...`（而不是 guest 视角的
`/data/data/com.sandbox.probe`），该路径**真实存在** ⇒ `open` 当然成功，与"是否被翻译"无关。

**判据修正（待做）**：H1 不要用 `dataDir`，改用**guest 包名拼死路径**：

```cpp
const std::string target = "/data/data/" + pkg + "/files/native_dlsym.txt";
```

这样该路径在容器里**必然不存在**：`dlsym` 调用成功 ⇒ 被翻译；`errno=2` ⇒ 绕过（预期）。

> 这条正是"探针自己的构造错误"（规则 18.4 的「编码错误 —— 测试构造错」）。修完重编一次探针即可。

### 2.3 `W-ext-private / W-ext-public` —— **未取到数据，已停止**

- `LAUNCH_ACTIVITY com.sandbox.probe.WebViewProbeActivity` → 容器返回 `Success`；
- VAMS 日志确认**真的起了**：`→ com.nextvm.app.stub.P1$Standard00 (task=1004)`；
- 但三处候选位置都**没有** `wvprobe-result.txt`：
  - `<instance>/files/wvprobe-result.txt`
  - `<instance>/sdcard/wvprobe-result.txt`
  - `<instance>/external_files/wvprobe-result.txt`
- `dumpsys activity` 的栈顶是 `com.nextvm.app/.stub.P0$Standard00 t1813`（ProbeActivity 的 task），
  WebViewProbeActivity 在 **P1 slot / task 1004** —— 起了但不在前台。
- 尝试 3 次（45s / 再 40s / 直接查文件）均无结果 ⇒ **按"某一步频繁失败即全部停止"停机，未再重试**。

**下一步诊断（未执行）**：

1. 查 P1 slot 的进程是否 bind 成功（`breadcrumb-<P1 pid>.log`），WebViewProbeActivity 可能崩在 `onCreate` 早期；
2. 把 `openOutputs()` 提到 `onCreate` **第一行**（现在在 UI 构建之后），确保"只要 Activity 起来就有文件"；
3. 或改用 `getExternalFilesDir()` 作为**唯一**输出点（减少一个"容器映射"变量）。
