# 分析：一次异常后「次次异常」是什么故障

- 日期：2026-11-25
- 触发：用户观察「一次安装、执行异常，guest 就次次异常」；卸载后才恢复
- 结论：**这是"持久化污染"型故障，不是内存态 bug**。
  `254324b` 基线修掉了其中的原因之一（ensureDir），但**没有污染自愈能力** —— 需要新增检测。

---

## 一、先排除一个误解：`ensuredDirs` 不会造成"次次异常"

上游那个 `ensureDir` bug 是：

```kotlin
if (ensuredDirs.add(path)) file.mkdirs()   // 先登记、后创建、丢弃返回值
```

但 `ensuredDirs` 是**内存 Set**（`SandboxManager` 的字段）→ **进程重启就重置**。
所以它最多导致"**本次进程内**该目录永远建不出来"，**不会**造成"次次异常"。

**所以"次次异常"另有原因** —— 必须在磁盘上找。

---

## 二、能造成「次次异常」的候选（都持久化在应用数据里）

| # | 候选 | 机制 | 卸载后是否恢复 | 可观测性 |
| --- | --- | --- | --- | --- |
| **1** | **沙箱目录磁盘上缺失** | `mkdirs()` 因为父路径/权限失败，每次启动都失败 | ✅（数据被删） | `ensureDir mkdirs FAILED path=...`（v144 加的日志） |
| **2** | **沙箱目录名/结构不合法** | 实例 id 里带非法字符（`:` `/`），导致路径异常 | ✅ | 目录列表 |
| **3** | **容器状态文件损坏** | SharedPreferences / DB 里记着"guest 已安装但 APK 不存在" | ✅ | 无（**当前是盲区**） |
| **4** | **appops 授权丢失** | 卸载重装后 `MANAGE_EXTERNAL_STORAGE` 回到 `default` | ✅（重装同样丢） | `appops get` |
| **5** | **vivo 的 GC JIT delay 状态** | `Close vivo delay for GC JIT` 卡在半开状态 | ？ | logcat 有该行 |

**用户的现象"卸载才好"** 与 1/2/3 都吻合（卸载会删掉整个 `/data/user/0/com.nextvm.app/`）。

---

## 三、`254324b` 基线修了什么、没修什么

| 项 | 状态 |
| --- | --- |
| `ensureDir` 不再"登记失败路径" | ✅ 已修（v144，在 `254324b` 里） |
| `mkdirs` 失败时写 **error 日志** | ✅ 已修（排查第一线索） |
| bind 时**预建目录树**（`ensureAppDirsReady`） | ✅ 已修（v144） |
| **已损坏的沙箱目录自动清理/重建** | ❌ **没有** |
| **容器状态文件的一致性校验** | ❌ **没有** |
| **appops 授权缺失的检测/提示** | ❌ **没有** |

**所以**：`254324b` 能**防住**"新建实例时目录建不出来"，但**不能自愈**已经损坏的实例。

---

## 四、新基线提供的追踪能力（这是关键改进）

`baseline-v150` 分支植入了诊断层，故障复现时能看到**结构化证据**：

### 4.1 `ensureDir` 失败会显式报错

```
E NextVM-SandboxMgr: ensureDir mkdirs FAILED path=/data/user/0/com.nextvm.app/files/virtual/data/mark.via_xxx/sdcard
```

→ **直接指出哪个目录建不出来**（这是"次次异常"最可能的答案）

### 4.2 `checks.log` 会记录每一步

```
0005 path.v142 registerRules ok=false expected=kotlin=11 native=11 actual=kotlin=0 native=0 reason=no_rules_registered
0012 application.5 initContentProviders ok=skip reason=dir_missing
```

→ 从"哪一步开始失败"倒推污染点

### 4.3 生命周期序列会暴露"起不来的位置"

```
S lifecycle recorder_installed
S lifecycle pre_created:MainActivity
（如果 pre_created 之后没有 created，说明 Activity 创建阶段挂了）
```

## 五、建议新增的「污染检测 + 自愈」（设计，未实现）

### 5.1 启动时做一次沙箱自检

```kotlin
/** 返回 null = 健康；否则返回诊断字符串。 */
fun selfCheck(instanceId: String, pkg: String): String? {
    val appDir = getAppDir(instanceId)
    if (!appDir.isDirectory) return "appDir missing: $appDir"
    val need = listOf("files", "cache", "sdcard", "databases")
    for (n in need) {
        val d = File(appDir, n)
        if (!d.isDirectory && !d.mkdirs()) return "cannot create $d"
    }
    // APK 文件是否还在（状态文件说装了但文件没了）
    val apk = File(dataRoot.parentFile, "apks/$pkg.apk")
    if (!apk.exists()) return "apk missing: $apk"
    return null
}
```

**调用点**：`launch()` 之前；失败时**不静默**，通过 `checks.log` + UI 提示暴露。

### 5.2 一条"一键重建实例"的路径

现在只能"卸载重装"（丢全部实例）。
应提供：**删除单个实例的沙箱目录 + 重新安装该 APK**，不动其它实例和 appops 授权。

### 5.3 `terminateApplication` 时的一致性检查

```
实例标记为已安装 -> APK 文件必须存在
                   沙箱目录必须存在
                   -> 否则记 error（说明上次清理不完整）
```

## 六、现在能做的验证

用 `baseline-v150` 装机后，若"次次异常"复现，按这个顺序查：

```powershell
# 1) 是否有 ensureDir 失败
adb logcat -d -b all | Select-String "ensureDir mkdirs FAILED"

# 2) checks.log 里哪一步先失败
adb shell "am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.CAT_OUT --es file checks.log"
adb logcat -d -s CmdReceiver

# 3) 沙箱目录是否真的存在
adb shell "am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LIST_OUT"
```

**如果 1) 有输出** → 就是目录建不出来（最可能）
**如果 1) 没有、2) 某步 ok=false** → 是逻辑失败
**如果 1) 2) 都正常但 UI 仍不出来** → 转向渲染/生命周期（用 `lifecycle` 序列看卡在哪）

## 七、残留 logcat 的实测证据（2026-11-25，卸载后仍可读）

`
10:38:38.301 WVP: PREP /sdcard/wvprobe19.html FAIL:
             FileNotFoundException: /sdcard/wvprobe19.html: open failed: EPERM
10:38:38.233 WVP: OUT [filesDir] .../files/wvprobe-result.txt  OK
             OUT [externalFiles] .../sdcard/Android/data/com.sandbox.probe/files/...  OK
             OUT [externalRoot] /storage/emulated/0/wvprobe-result.txt  FAIL EPERM
`

**两条结论**：

1. **/sdcard 直写 EPERM 不是容器 bug** —— 探针跑在**容器主进程**，
   而主进程按 P0-3 设计**不装 hook**（initNativeHooks skip: container main process），
   所以 /sdcard 没被重定向。而 ilesDir / xternalFiles（走 VirtualContext）都 OK。
   → **探针应该只用那两个通道**。

2. **ppops 授权已丢失** —— 卸载会清掉 MANAGE_EXTERNAL_STORAGE。
   **装新基线后必须重新授权**：
   `powershell
   adb shell appops set com.nextvm.app MANAGE_EXTERNAL_STORAGE allow
   `
   否则 guest 导入 APK（从 `/sdcard/Download/`）会报 `APK file not found`。

**注意**：这次日志里**没有** `ensureDir mkdirs FAILED` 的痕迹 ——
因为装的 upstream-baseline **不含 v144 的 ensureDir 修复**，没有这条日志。
换成 `baseline-v150` 后就能看到。
