## 三、实测到的关键事实

**用户操作（搜索 + 清空）之后，`offline` 目录在本次进程里 `list0` 访问次数 = 0。**

```
本次进程 javaIo 记录（全部）：
  #0 list0 err=20 .../apks/mark.via_xxx.apk
  #1 list0 err=20 .../apks/com.sandbox.probe_xxx.apk
  #2 createF err=17 .../oat/mark.via_xxx.apk.cur.prof
  #3 list0 err=20 .../apks/mark.via_xxx.apk
  #4-#6 open err=2 .../lib/libDexHelper.so
```

对比 14:0x 那次进程：
```
ufs list0 [xlat]: .../files/offline -> 4 entries
ufs-alias stat [xlat]: .../offline/百度一下.mht -> size=497100
```

**→ 说明 `ha/e.b()` 在最近这次根本没执行。**

## 四、推论（**这一条是推测，未经实测**）

进入离线页面时：

1. `onViewCreated` → `z3()` 只注册 TextWatcher，**不发射初始值**（`u8/d` 只 `addTextChangedListener`）
2. `y3()` 只 `observe` 两个 LiveData，**两个 LiveData 都没被 postValue**
3. 所以你看到的是：**列表空**（`S2` 没被调）+ **空视图也不显示**（`T2` 没被调）= **完全空白**
4. 用户搜索 → Rx 链路 `debounce → observeOn → autodispose` 若中断，`eb/m` 不执行 → `t(query)` 不调用 → 依然不加载

**三个可疑断点**（需实测确认，按可能性排序）：
| # | 断点 | 可疑原因 |
| --- | --- | --- |
| 1 | `autodispose`（`.as(...)`） | 依赖 `Fragment.viewLifecycleOwner` 达到 STARTED；容器里 view lifecycle 可能未正确派发 → 立即 dispose |
| 2 | `debounce(300ms)` | 走 `Schedulers.computation()`；线程池异常则事件丢弃 |
| 3 | `observeOn(mainThread)` | 需要正确主线程 Looper（容器用 ActivityThreadHook 接管 mH） |

**无法解释的矛盾**：真机上不搜索也有结果，但代码里首次进入确实只有 TextWatcher 一条触发路径。可能真机上 `setText(q)` 时 `q` 非空（有历史搜索词），也可能还有一条没找到的触发路径。

## 五、下一步唯一能拿实测数据的办法

静态分析已到极限。要确认上面三个断点，必须让 via 自己打日志。

**方案 A：重写 `ha/b`（8 个方法）作为补丁类**（推荐）
- 用 `javac` 写 `package ha; public class b implements ha.g {...}`，在 `b(Z)`/`c(String)` 里打 `Log.d`
- 用 `d8` 编成 `patch.dex`，**放进 APK 并命名为 `classes.dex`**，原 `classes.dex` 改名 `classes2.dex`
- dex 加载顺序决定同名类以先加载者为准 → 补丁类生效
- 需要的 stub：`ha.g`(接口, 传 `b(Z)`/`c(String)`/`a(n9.d)`)、`ha.h`(2 方法)、`n9.d`(若干 getter)
- **障碍**：需要 `smali`/`baksmali` 或至少 `d8` + stub；`smali` 从 Maven/华为源都 404，GitHub release 也拿不到（代理 SSL 断连）

**方案 B：容器侧给 `Fragment.getViewLifecycleOwner()` 打日志**
- 只能看 lifecycle 状态，看不到 `eb/m` 是否执行
- 要构建容器

**方案 C：在容器里 hook `y5/f.M(List)` 的调用**（Adapter 设数据）
- 若 Adapter 收到空 list → 说明 `m()` 被调了但 list 空
- 若 Adapter 从未被调 → 说明 `m()` 没执行
- **实现方式**：`y5/f` 是 via 的类，Java 方法无法用 RegisterNatives hook；但可以观察它内部调用的 native 方法

**方案 D：用 python 直接改 dex 的字符串常量**（不改逻辑）
- 只能改日志文本，对我们的需求无用
