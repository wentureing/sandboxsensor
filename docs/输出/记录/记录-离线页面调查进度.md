## 二、环节 5：`0 entries` 的根因与修复

### 现象

```
ufs list0 [xlat]: <sandbox>/sdcard/Android/data/mark.via/files/offline -> 0 entries (EMPTY)
```

路径翻译对了、目录里确实有文件、`opendir` 也成功（否则会走失败分支返回 null），
但一个条目都读不到。

### 根因：`readdir` vs `readdir64`

AOSP 的 `UnixFileSystem_md.c`：

```c
while ((ptr = readdir64(dir)) != NULL) {
```

我们原来用的是：

```cpp
struct dirent* e = readdir(d);      // ← 符号与结构体都不对
```

在 64 位 bionic 上，`struct dirent` 与 `struct dirent64` 的 `d_ino` / `d_off` 字段宽度不同。
用 `readdir` 填 `struct dirent` 再读 `d_name`，偏移是错的 → **读到的"名字"是空/垃圾** →
被 `if (n == nullptr) continue` 或 `strcmp` 过滤掉 → 最终 0 条。

### 修复（`98be504`）

```cpp
struct dirent64* e = readdir64(d);   // 与 AOSP 一致
if (e == nullptr) {
    if (errno != 0) { 记录 + LOGE("ufs list0: readdir err=...") }
    break;                            // 区分「遍历结束」与「出错」
}
```

第二个改动也很重要：旧实现 `if (e == nullptr) break;` 把"出错"当成"目录为空"，
这是"文件在但列表空"最难查的原因。

### 实测结果（`b992ba4` 装包）

```
ufs list0 [xlat]: .../files/offline -> 0 entries (EMPTY)    ← 放文件之前
ufs list0 [xlat]: .../files/offline -> 0 entries (EMPTY)    ← 同上
ufs list0 [xlat]: .../files/offline -> 3 entries            ← ✅ 放 3 个 .mht 之后
```

**`readdir err=` 无输出** → 没有读目录错误。

**结论：`list0` 现在能正确列举沙箱目录的内容。**

## 三、环节 6：主页空白的根因与修复

### 根因（两层）

**第一层：WebView 渲染在 isolated 进程**

```
13698  uid=10373  mark.via
18326  uid=99613  com.google.android.webview:sandboxed_process0:...
 4308  webview_zygote                                    ← 18326 的父进程
```

该进程 **hook 日志完全为空** —— 没有 `installJavaIoHooks` / `NextVM` 记录。
路径字符串交给 WebView 后，解析发生在那里，**不受我们的路径翻译约束**。

**第二层：假路径在真机上不存在**

via 拼的是 `getFilesDir() + "homepage2.html"`。`pathFidelity` 让 `getFilesDir()`
返回 `/data/user/0/mark.via/files`，而真实文件在
`/data/user/0/com.nextvm.app/files/virtual/data/<inst>/files/homepage2.html`。

isolated 进程打开前者 → `ERR_FILE_NOT_FOUND` → 主页空白。

### 关键证据

```
W18:  file:///data/user/0/com.nextvm.app/files/wvprobe18.html  -> ERR_FILE_NOT_FOUND （文件不存在）
W35a: file:///data/user/0/com.app.hider.master.pro.cn/gaia/data/user/0/com.sandbox.probe/files/wvprobe_bom.html
      -> WVPAGE_OK                                             （gaia 形态，文件存在 -> 读到了）
```

**W35a 证明 isolated 进程能读宿主私有目录**，只要路径真实存在。

### 修复（`c3c918a`）

```kotlin
private val contentPathsUseReal: Boolean = false

private fun contentDir(sandboxDir: File, synthetic: () -> File): File =
    if (pathFidelity && !contentPathsUseReal) synthetic() else sandboxDir
```

8 个内容目录（files / cache / code_cache / no_backup / external files /
external cache / obb / media）**返回真实沙箱路径**；
`getDataDir()` 与 `ApplicationInfo.dataDir` **保留合成路径**（反双开检测看那里）。

### 实测结果（`b992ba4` 装包）

- **没有 `ERR_FILE` / `file://` 错误**（之前 W18 那种）
- `homepage2.html` 存在于 `<sandbox>/files/`（6333 字节）

## 四、代价（明确接受）

`getFilesDir()` 现在返回真路径 → **via 能直接看出在容器里**，最严重的是：

```java
// 框架不变量被破坏（真机上永远相等）
getFilesDir().getParentFile() != getDataDir()
```

详见 `docs/设计/设计-讨论-假路径换真路径的可发现性.md`。
**彻底解决要等内置 WebView**（那时渲染进程归容器所有，可以切回假路径）。
