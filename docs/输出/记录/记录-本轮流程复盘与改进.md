## 二、流程改进（已写进 AGENTS.md，可直接执行）

### 1. 判定只读文件（本轮最大收益）

| 判定对象 | 读什么 |
| --- | --- |
| 容器是否就绪 | `run-as … ls files/`（+ 固定等 10s） |
| guest 是否导入 | sandbox 里出现 `<pkg>_<ts>` 实例目录 |
| 自检结果 | `files/checks.log` 的 `hookcheck ok=N fail=N` |
| 探针结果 | `probe-report.json`（`entries` 的 `status` 分布） |
| guest 启动到哪 | `breadcrumb-<pid>.log` 的 `bind complete` / `onActivityResumed` |

**理由**：文件是唯一稳定通道（logcat 会因 uid、ROM、缓冲被吞；`dumpsys` 会随版本变）。

### 2. 每步 1 次 adb（设备端等待）

```powershell
# 旧：PC 端每秒一次，最多 40 次
for i in 1..40 { if (Sh "ls ...") { break }; sleep 1 }
# 新：设备端 until + timeout，1 次拿到结果
Sh "run-as $Pkg timeout 25 sh -c 'until ls $Data | grep -q $pkg; do sleep 0.2; done; ls $Data | grep $pkg | tail -1'"
```

### 3. 多步逻辑用 Node（规则 19）

`execFileSync('adb', ['-s', serial, ...])` **数组传参**，从源头消灭引号问题；
二进制走 `Buffer`；输出可直接 `JSON.parse`。pwsh 只留"单行只读 / git / gradle / CI"。

### 4. 写脚本前先手工验证"一条命令"

本轮多次出现"脚本写完才发现引号/参数不对"。**修正习惯**：
把设备端那段 `sh -c '...'` 先在终端**手敲一遍**看输出，再包进脚本。

### 5. CI 归因前置

- `module-test` 现在**编译单独成 step**：红了就是编译错，"没有测试报告"不再需要猜；
- 失败时 job summary 直接给 `e: file` / `Unresolved` / `FAILED` 行，**不用下载日志**；
- 本地 6 项毫秒级检查（`kotlin-lint` / `check-imports`（含嵌套类）/ `check-duplicate-imports` /
  `check-diag-channels` / `check-probe-ids` / `gen-*-–check`）先跑一遍。

### 6. 拆分的两个"设计约束"（为让等价检查可用）

| 约束 | 原因 |
| --- | --- |
| 新函数**不用函数类型参数**（改用列表/回调对象） | `->` 破坏花括号配对，`check-refactor-equivalence` 提取失败 |
| 新函数**不给参数默认值 `= {}`** | 默认值会被当函数体起点 |

这两条不是代码风格偏好，而是**为了能用机器证明"逻辑没变"**。
