## 一、本次故障（2026-11-25 实机）

### 现象

```
启动 guest 后 UI 卡死，guest 未能出现 UI
```

### logcat 关键片段

```
10:39:28  Close vivo delay for GC JIT
10:39:37  ApkAssets: Deleting an ApkAssets object '<empty> and
            /data/user/0/com.nextvm.app/files/virtual/apks/mark.via_...apk' with 1 weak references
10:39:37  VirtualEngine: Launching: Sandbox Probe
10:39:37  NextVM-Native: Path redirect added ×6
10:39:39  ActivityTaskManager: Displayed com.nextvm.app/.stub.P1$Standard00: +1s674ms
10:39:48  dgc_arg: request backgroud gc, has_act=1, state=0     ← 之后完全静默 2 分钟
```

### 根因：上游 `SandboxManager.ensureDir` 的 bug

```kotlin
// 上游原实现
private fun ensureDir(file: File): File {
    if (ensuredDirs.add(file.absolutePath)) {   // ① 先登记为"已确保"
        file.mkdirs()                            // ② 再创建，且丢弃返回值
    }
    return file
}
```

**两步错**：
1. **先登记、后创建**
2. **丢弃 `mkdirs()` 的返回值**

**后果**：一旦首次创建失败（启动早期父目录链未就绪），该路径被**永久记忆**为"已确保"，
之后永不重试 → guest 拿到"登记为已创建但实际不存在"的目录。

fork 的注释里早已写明：「**Via 的 fontDirectory 崩溃就是这么来的**」。

### 修复（已移植，`173c4b9`）

```kotlin
if (ensuredDirs.contains(path) && file.isDirectory) return file  // 已登记且确实存在才返回
val created = file.mkdirs()
val ok = created || file.isDirectory                             // 并发下别人建好也算成功
if (ok) ensuredDirs.add(path)
else { ensuredDirs.remove(path); Timber.e("ensureDir mkdirs FAILED path=%s", path) }
```

## 五、方法论：怎么系统性找「上游缺什么」

```powershell
# 1) 逐文件对比上游与 fork
$up = "tools/tmp/upstream-ShitJumpingVM"
Get-ChildItem -Recurse $up -Include *.kt |
  Where-Object { $_.FullName -match "\\src\\main\\" } |
  ForEach-Object {
    $rel = $_.FullName.Replace((Resolve-Path $up).Path + '\','')
    $local = "_ref/ShitJumpingVM/$rel"
    if ((Test-Path $local) -and
        (Get-FileHash $_.FullName).Hash -ne (Get-FileHash $local).Hash) { $rel }
  }

# 2) 对差异文件逐函数做等价性检查（忽略插桩）
node tools/lint/check-refactor-equivalence.mjs `
  --old-file <上游文件> --old-fn <fn> `
  --new-file <fork文件> --new-fn <fn> `
  --ignore "DebugTrace\.|DiagnosticsHolder\.|preCreateSeq"
```

**教训**：把上游当"标准"之前，必须先确认它**修过的 bug 我们有没有** ——
否则会把"上游的 bug"当成"标准行为"来固化。
