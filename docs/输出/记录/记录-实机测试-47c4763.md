## 三、宿主 external 出现文件 —— 落盘时间与归因

### 3.1 精确时间（设备时间）

| 位置 | 文件 | mtime |
| --- | --- | --- |
| **宿主** | `probe-early.json` | 21:14:09.**241** |
| **宿主** | `fsprobe/`（目录） | 21:14:09.**317** |
| **宿主** | `offline/probe-a.mht`、`probe-b.txt` | 21:14:09.**317** |
| **宿主** | `probe-report.json`（14425 B） | 21:14:09.**405** |
| 沙箱 | `.../sdcard/Android/data/com.sandbox.probe/files/offline/probe-a.mht` | 21:14:09.**413** |
| 沙箱 | `<inst>/files/probe-report.json`（14117 B） | 21:14:09.**457** |

同一进程（pid 15114）运行窗口内，**宿主先写、沙箱后写，间隔 ~50–100ms**。

### 3.2 归因（读探针源码确认，非推测）

| 宿主文件 | 来源 | 性质 |
| --- | --- | --- |
| `fsprobe/` | `ProbeRunner.probeFs()` 的 **F08**：`Environment.getExternalStorageDirectory() + "/Android/data/<opPkg>/files/fsprobe"`，注释原文"**若容器兜底，应被重定向到沙箱；若否，会真的建在宿主**" | **探针故意的写穿检测**；`made=true` = 未兜底 |
| `offline/probe-a.mht`、`probe-b.txt` | 同一批 `probeFs()` 操作（F09 用 `getExternalFilesDir("offline")`，J08 报告该 API 返回**沙箱**；宿主 side 出现说明该次调用链里仍有宿主形态写入） | 探针写入检测 |
| `probe-early.json` | `Report.flushEarly()` 的"外部存储副通道"（`ctx.getExternalFilesDir(null)`，early 阶段 ctx 尚未虚拟化） | 已知设计 |
| `probe-report.json` | `Report.flush()` 的外部副通道（宿主态 ctx 的那一次） | 已知设计 |

### 3.3 结论

- **不是回归**：宿主文件全部产生于本轮探针运行（时间戳可证），且对应探针**主动探测**的代码路径
  （F08 注释明确"若否会真的建在宿主"）。
- **暴露的真实边界**：字面量宿主路径（`Environment` 拼出来的）与 early 阶段的 `getExternalFilesDir`
  **不会被兜底**——这正是 `javaIo=0` 下"Java 层字面量不翻译"的同一根因（与 J26/J27 同源）。
- 通过 **Context API** 的写入（`getExternalFilesDir("fsprobe")`/`"offline"`，J08/F01/F09/F14）
  落在**沙箱**，这部分正常。
