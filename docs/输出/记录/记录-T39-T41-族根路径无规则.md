# 记录：T39 / T41 失败 —— 路径族的「根」形态没有规则覆盖

- 日期：2026-11-25
- 结论：**`syntheticDataDir(pkg)` 返回的 `/data/user/0/<pkg>`（无尾斜杠）不被任何规则翻译。**
  Java `NativeHookBridge.translatePath` 与 C++ `redirect_path` 都只做 `startsWith` 前缀匹配，
  而 `setupAppRedirections` 只注册**带尾斜杠**的 `/data/data/<pkg>/` 与 `/data/user/0/<pkg>/`。
- 性质：**真实缺口**，不是测试写错。触发条件是 guest 对「dataDir 本身」的访问
  （`File(getDataDir()).exists()` / `stat(dataDir)` / `listFiles(dataDir)`），
  真机上这些调用成功，容器里落空路径。
- 与 A 阶段无关：A 阶段（`6b5cfbe`）的 10 个新用例 H1–H10 **全部通过**，红的是 T39/T41。

## 三、代码链路（三处，缺一即不成立）

| 层 | 位置 | 事实 |
| --- | --- | --- |
| 合成路径 | `core/model/ProcessSlot.kt:193` | `syntheticDataDir(pkg) = "/data/user/0/$pkg"`，**无尾斜杠**（与 AOSP `getDataDir()` 一致，不能改） |
| 规则注册 | `core/hook/NativeHookBridge.kt:412-419` | 只注册 `/data/data/<pkg>/`、`/data/user/0/<pkg>/`（**带斜杠**） |
| 匹配 | `core/hook/NativeHookBridge.kt:775-796` | `originalPath.startsWith(from)` 最长前缀；根形态既非前缀，也不在 `hiddenPaths` |
| **native 同源** | `core/hook/src/main/cpp/native-hook.cpp:229-258` | `redirect_path()` 用 `path_str.compare(0, from.size(), from)`，**同样只做前缀匹配** |

**关键点：这个缺口在 L4（Java `translatePath`）和 L5（C++ `redirect_path`）各存在一份。**
只修 Java 会让「Java 层看到沙箱、native 层仍落空路径」——典型的"半通"状态，比全不通更难查。

## 四、为什么不能照抄 external/obb/media 的「无尾斜杠变体」

`setupAppRedirections` 对 external/obb/media 都注册了 `trimEnd('/')` 变体（:433-464），
因为 `getExternalFilesDir()` 返回的正是无斜杠形态。但 **data 目录不能照抄**：

```
加规则 /data/user/0/mark.via          （无斜杠，前缀）
  -> /data/user/0/mark.via.pro/x  startsWith 命中 -> 翻译到 mark.via 的沙箱
```

`T15 包名互为前缀不串味` 正是守这条（`/data/data/mark.via.pro/a` 必须原样返回）。
也就是说：**根形态需要的是「精确匹配」，不是「更短的前缀」**，而现有规则表只有前缀语义。

| **A. 把「等于某规则去斜杠形式」并入匹配语义（推荐）** | Java 匹配条件加 `exactRoot`；C++ `redirect_path` 加同条件；根形态命中返回 `to.trimEnd('/')` | 改 2 处匹配 + 2 个文件；**不新增规则**（规则表快照不变） | 语义最小、契约成立 |

| C. 改测试，登记为已知缺口 | T39 把 dataRoot 用例改成「允许未翻译」并写进镜像文档「约束与坑」 | 零代码风险 | 把「只误导、不危害读写」契约降级，**不推荐** |

### 方案 A 的实现要点（供 B 阶段复用）

```kotlin
// NativeHookBridge.translatePath 内，前缀判定旁增一个"族根"判定
val isRootForm = from.endsWith("/") &&
    originalPath.length == from.length - 1 && from.startsWith(originalPath)
if ((originalPath.startsWith(from) || isRootForm) && from.length > bestMatch.length) {
    bestMatch = from; bestRedirect = to; bestIsRoot = isRootForm
}
// 命中族根时不要拼 "/"：原路径没有尾斜杠，结果也不该有
if (bestIsRoot) return bestRedirect.trimEnd('/')
```

C++ 侧同条件：

```cpp
bool root_form = redirect.first.size() == path_str.size() + 1 &&
                 redirect.first.back() == '/' &&
                 redirect.first.compare(0, path_str.size(), path_str) == 0;
```

**约束（必须同时满足）**：

1. Java 与 C++ **必须同一次提交一起改**，否则层间行为分叉；
2. 根形态命中返回 `trimEnd('/')`，保证 `getDataDir()` 与其 `getFilesDir().getParentFile()`
   形态一致（父子关系自洽，见 `docs/设计/设计-澄清-欺骗与隔离与合成路径.md` 的 🔴 #1）；
3. 既有断言不受影响：`translatePath("/data/data/<pkg>/")` 仍返回带斜杠目标（T 系列 :142-143）；
4. `getPathRedirectSnapshot()` 输出的是规则表，**规则数不变** → B 阶段「snapshot 改造前后 diff 为空」判据仍然可用。
