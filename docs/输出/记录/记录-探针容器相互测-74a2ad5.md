## 二、执行步骤（全部显式，无自动触发）

```powershell
adb uninstall com.nextvm.app                      # 干净安装（丢 appops + 沙箱）
adb install dist/container-74a2ad5.apk
adb shell appops set com.nextvm.app MANAGE_EXTERNAL_STORAGE allow
adb shell am start -W -n com.nextvm.app/.MainActivity
adb push dist/probe-74a2ad5.apk /data/local/tmp/probe.apk
adb shell setprop debug.probe.suite round
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.INSTALL --es path /data/local/tmp/probe.apk
adb shell am broadcast -n com.nextvm.app/.CmdReceiver -a com.nextvm.cmd.LAUNCH_ACTIVITY \
  --es pkg com.sandbox.probe --es activity com.sandbox.probe.ProbeActivity
# 结果文件：<instance>/files/probe-report.json
```

→ **诊断通道在容器内正常产出**；`DiagChannel`/`DiagFiles` 收编没有破坏落盘。

### 3.2 套件过滤

- `P*`（24 项）、`N*`（15 项）全部 `skipped` = **39 项**；
- 校验脚本：`非 round 前缀是否全部 skipped` → **全部正确**。

→ 说明 `put()` 过滤 + **native 结果过滤修复（`74a2ad5`）**都生效（N 系列此前会漏跑）。

### 3.3 两个 fail 的归因（**已知限制，非本次回归**）

| ID | 现象 | 归因 |
| --- | --- | --- |
| J26 | 写 `/data/data/com.sandbox.probe/files/literal.txt` → `ENOENT` | 字面量宿主路径需要**翻译**才落沙箱；而 `debug.nextvm.javaIo=0`（Java 层 hook 不装）+ `libjavacore.so` 不被 GOT patch → 该写入不被翻译，直接 open 真实路径 → 不存在 |
| J27 | 同上，`/data/user/0/com.sandbox.probe/...` | 同上 |

这正是本项目记录的**层间不一致**（Java 层不翻译 / native 层翻译）：`D` 系列与 `F` 系列（走 Context 目录方法的路径）都正常，只有**硬编码字面量**路径失败。

## 四、结论

1. **诊断通道收编在真机容器内生效**（D01–D05 全 ok）；
2. **探针套件化生效**（39 项 skipped，无漏跑）；
3. 容器与探针可互相验证：探针在 guest 内能读到容器产出的诊断文件（breadcrumb/checks/stackdump 同名规则一致）；
4. J26/J27 是"字面量路径 + javaIo=0"的已知限制，可作为后续"是否打开 Java 层 hook"的对照基线。
