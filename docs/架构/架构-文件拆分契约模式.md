# 架构：文件拆分 —— 「契约文件 + 补充文件」模式

- 日期：2026-11-24
- 原则（用户定）：**单个代码文件超过 1000 行，很可能职责混杂或架构不良。**
  允许**一个文件写明契约，其他文件补充功能**。

---

## 一、模式定义

### 契约文件（`Xxx.kt`）

保留**最小可理解集合**：

| 内容 | 说明 |
| --- | --- |
| 类/对象声明与构造 | 依赖注入点、生命周期入口 |
| **共享状态** | 字段改为 `internal`，供补充文件访问 |
| **公开 API** | 外部调用者看到的那一层（门面） |
| 类级 KDoc | **写清契约**：职责、不负责什么、偏差登记、补充文件清单 |

**目标：契约文件 ≤ 400 行**，读它就能理解这个组件的边界。

### 补充文件（`XxxYyy.kt`）

用 **`internal` 扩展函数**（或 `internal class`）实现具体功能：

```kotlin
// LaunchSupport.kt
internal fun ActivityThreadHook.registerPendingResourceInjection(...) { ... }
```

- 扩展函数可直接访问 `internal` 成员，**不需要 getter 噪音**
- 同 module 可见，不扩大对外 API
- 每个补充文件对应**一个职责**，同样写镜像文档

### 命名约定

| 契约文件 | 补充文件 |
| --- | --- |
| `ActivityThreadHook.kt` | `TransactionInterceptor.kt`、`LaunchSupport.kt`、`ApkWatchdog.kt` … |
| `NativeHookBridge.kt` | `PathRedirectRegistry.kt`、`ProcSpoofing.kt` … |
| `VirtualApplicationManager.kt` | `GuestPathSetup.kt`、`GuestBootSupport.kt` … |

## 四、每次拆分的硬性产物

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| 契约文件 KDoc | 代码内 | 职责 / 不负责 / **补充文件清单** / 偏差登记 |
| **镜像文档** | `docs/代码镜像/<同路径>.md` | 规则 7：职责 / 函数 / **偏差登记** / 约束与坑 |
| 编译校验 | — | 括号 + 一次容器构建 |
| 行为不变的证据 | — | 拆分**不改逻辑**，只移动；构建成功即视为通过 |

---

## 五、拆分时的安全守则

1. **只移动，不改逻辑**（要改逻辑另开变更，避免"拆分 + 改行为"混在一起无法归因）
2. 字段从 `private` 改 `internal` 时，**只改可见性，不改名**
3. 每次拆 1–2 个文件，**构建一次**（避免一次改太多定位困难）
4. 拆完先查"未使用 import"（Kotlin 会警告，不报错，但留着会让人以为还在用）
5. 拆分与镜像文档**同一个提交**
