## 二、逐项判断

### 🔴 `VirtualApplicationManager`（4540 行）—— 该拆，且本轮改动加剧了它

它现在同时承担：

| # | 职责 | 本轮的增量 |
| --- | --- | --- |
| 1 | `bindApplication` 主流程（framework / legacy 两条路径） | — |
| 2 | `LoadedApk` / `ApplicationInfo` 反射注入 | v143 假 dataDir |
| 3 | 路径重定向规则注册 | v142 |
| 4 | 目录树预建 | v144 |
| 5 | `ActivityThread` 字段 patch（`mInitialApplication`） | v138 |
| 6 | breadcrumb / 诊断回调注册 | 已有 |
| 7 | WebView 预热与监控调度 | 已有 |
| 8 | stack dump / DexMemDump / StateProbe 调度 | 已有 |

**结论**：这是本项目最该拆的文件，拆完 `bindApplication` 能回到"只有流程"的样子。

### 🟡 `native-hook.cpp`（6547 行）—— 该拆，但**现在不能动**

它包含：GOT/PLT patch 引擎 + 22 个 hook 实现 + JNI 桥 + seccomp + `/proc` spoof + 路径规则表。

**为什么现在不动**：当前正在排查 Via 崩溃与 WebView MIME，C++ 拆分属于"改地基"，
一旦出问题会和现有故障混在一起，违反本项目已有教训（"边想边改、越改越偏"）。
等故障收口后再拆，且拆完必须能跑通现有全部验证点。

### 🟢 `VirtualContext`（589 行 / 26 override）—— **不需要拆**

它的"大"是 Android `Context` 本身大，不是设计问题。真要优化只抽
"路径策略"（pathFidelity / syntheticDataDir 那套分支）即可，收益有限。

### ⚪ `AntiDetectionEngine`（805 行）—— 先决定去留

零调用。要么接线（并修它两个缺陷），要么删。拆它没有意义。

## 三、现在该做什么：只做"低风险抽取"

**原则：不碰核心逻辑，只把本轮新增的东西搬出去。**

| 抽取 | 从 | 到 | 收益 | 风险 |
| --- | --- | --- | --- | --- |
| 诊断/调试插桩 | `VirtualApplicationManager`（v142/v143/v144 的日志与判断） | `GuestDiagnostics.kt` | -100 行 | 极低（纯搬运） |
| 路径与目录准备 | 同上（`registerGuestRedirections` / `patchFrameworkDataDir` / `ensureAppDirsReady` 调用） | `GuestPathSetup.kt` | -150 行 | 低（逻辑不变，仅移动） |
| WebView 支撑 | 同上（Warmup/Watch/假 dataDir 判断） | `WebViewSupport.kt` | -60 行 | 低 |
| Java IO hook 安装 | `NativeHookBridge`（`installJavaIoHooks` + 诊断） | `JavaIoHooks.kt` | -90 行 | 低 |

做完这四项，`VirtualApplicationManager` 可从 **4540 → 约 4140**，`NativeHookBridge` 从 1076 → 约 990，
并且"本轮到底加了什么"在结构上一目了然（都在新文件里）。

**不做**：不动 `bindApplication` 的控制流、不动 native、不动 `VirtualContext` 的 override。

## 五、结论

| 问题 | 回答 |
| --- | --- |
| 有必要重构吗？ | **有，且 `VirtualApplicationManager` 已经到必须拆的程度**（4540 行 / 8 种职责） |
| 现在就大拆吗？ | **不**。正在排查 Via 崩溃与 WebView MIME，动核心 = 引入新变量 |
| 现在能做什么？ | **四项低风险抽取**（纯搬运，不碰控制流），把本轮新增代码归位 |
| 什么时候拆核心？ | 当前两个故障（Via 崩溃 / MIME）收口、回归通过之后 |
| 拆分必须先满足什么？ | ① `docs/现状/README.md` 的能力状态表可作为回归清单；② 拆分后探针 W38/W39/W40 与 Via 启动必须全过 |
